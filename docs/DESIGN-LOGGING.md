# 运行日志（M12 批一）

> 状态：**已交付**（`v0.74.0-铺设14`，R10）。批二（自动更新）见 `docs/TRACK-ROADMAP.md` R11。
> 判据与实现同在：本文件说的每一句，都在 `packages/agent-core/src/log/`、
> `apps/desktop/src/main/{log-store,logger}.ts`、`main/ipc/logs.ts`、
> `renderer/src/features/logs/LogCard.tsx` 里有对应代码与测试。

## 一、这份日志为谁而写

给"出了事之后的自己"，以及偶尔要看现场的用户。它必须能回答三个问题：

1. 这次用的是**哪份数据**（数据根 / 配置来源 / 本轮有没有自愈过）？
2. 界面**崩过没有**（渲染进程异常退出、ErrorBoundary 接住的渲染失败）？
3. 启动失败时**为什么**（并且在进程退出之前，这条已经写在盘上）？

## 二、形状

- **位置**：`<数据根>/logs/app-YYYY-MM-DD.jsonl`（本地日期分日，与审计同口径）。
- **一行一条 JSON**：`{ ts, level, scope, msg, data? }`。
- **分级**：`debug < info < warn < error`；门槛默认 `info`。
  排查时用环境变量 `JJ_LOG_LEVEL=debug` 开细节 —— **刻意不落配置**：
  多一个持久开关就多一个"被改坏了没人知道"的面，而要看细节的场合恰恰是"现在就要查"。

## 三、三条口径（与执行审计同源）

1. **构造即剔密**。`createLogRecord` 是唯一构造入口，落盘的是"已经可以见人"的形状：
   - 键名像密钥的（`isSensitiveEnvName`，与终端环境剔除**共用一张表**）**连值都不看**，替换为 `***`；
   - 正文与字符串值过 `maskSecrets`（与审计共用同一实现）；
   - 深度 > 4、数组 > 20、长串 > 1000 一律收敛，**并把"收敛过"写进结果**（截断不静默）。
2. **写坏不抛穿**。写失败只计数（`status().writeFailures` / `lastError` / 卡的 notice 上可见）；
   到当日上限（20000 条）停止追加并计数。日志坏掉不该让它记录的那件事跟着死，
   但**失败必须数得出、看得见**。
3. **不出本机**。只有文件这一条路：没有导出、没有网络、没有任何出站调用
   （接线锁扫四个日志模块源码，出现 `fetch` / `node:http(s)` / `node:net` 这些词直接红）。
   注意一条**如实**：启动记录里带本机数据根路径 —— 它是排查"用的是哪份数据"的第一要素，
   而日志文件本身就是本机文件。**将来若加导出功能，要过与审计同款的脱敏**（路径只留末两段）。

## 四、轮转

- 保留最近 **7 天**（含今天），启动时执行一次；**删了谁写在日志里**（轮转不静默）。
- 只认自家命名（`app-*.jsonl`）—— 同目录其它文件一根手指都不碰。
- 删不掉就留着（轮转失败不是数据丢失，下一次再试）。

## 五、写入的三种时刻（批一范围）

1. **启动**：数据根 / 配置版本 / 来源 / 是否自愈 —— 每条启动记录都写；
2. **渲染进程异常退出**：`render-process-gone` 带 `reason` 落一笔
   （这条以前只进控制台，打包之后谁都看不见）；
3. **启动失败**：写完之后**才** `app.exit(1)` —— `app.exit` 不等异步写，
   发射后不管等于这条最该被看到的记录永远到不了盘（与 `will-quit` 那次同形的坑）。
   另有渲染层 **ErrorBoundary 上报**（`LOGS_REPORT`）：级别固定为 error、形状有契约、过同一遍剔密 ——
   它是一份**上报**，不是一支能随便写账的笔。

**刻意不在批一**：全局 `uncaughtException` / `unhandledRejection` 钩子 ——
注册它等于**改变崩溃语义**（默认会崩的进程变得不崩），要单独定口径（批二评估）。

## 六、边界（如实）

- 渲染层普通 `console` 输出**不自动**进日志；渲染层只有 ErrorBoundary 上报这一条路。
- 日志文件不加密（与审计同：本机文件，落盘前已剔密）。
- 界面没有"清空日志"入口：保留期自动删；要立刻清，在文件夹里自己删。
- `data` 字段的记录只保证**可核对**（放进去时已洗过），界面不做二次加工 —— 加工点越多，越容易有一处忘了剔。
