## 四、怎么推到 GitHub（本仓的固定流程）

- 提交说明**一律中文**；一轮一个主题，**先建主体提交，再另建"台账回填"提交**（回填里写真实数字，不许提前写）。
- 版本号：每轮 **+minor**（`0.94.0` → `0.95.0`）；标签命名 `vX.Y.Z-<轨道词><N>`，
  例如 `v0.94.0-规整20`；**标签指向该轮主体提交**（不是回填提交）。
- 一轮的固定收尾顺序（缺一步就会被下一步问住）：
  开发 → 两遍复核（写进 `review/REVIEW-LOG.md`）→ 台账（PROGRESS / CHANGELOG / ROADMAP / CHECKLIST）→
  门禁 → 提交 → **在干净的已提交基线上**跑变异核对 → 打标签 → `git push` → **`git ls-remote` 核对远端 == 本地** →
  清理（`python scripts/cleanup.py` 预览 → `--apply`）→ 记忆归档。
- **绝不改写已推送的历史与标签**（不 `--force`、不 `git commit --amend` 已推的东西、不移动已推的标签）。
- `git reset --soft` 之后**必须先 `git reset` 清索引**，否则第一条提交会吞掉整批改动（踩过，写进记忆）。
- 网络会抖：`Failed to connect to github.com:443` 是实测出现过的，**有界重试**（本项目做法：最多 3–4 次，间隔 15–20s），
  重试成功也要如实记录"第几次成功"。

## 五、用什么凭证（以及为什么不能写死进仓库）

- **现役**：Git Credential Manager 浏览器授权拿到的 **OAuth 令牌**（`gho_` 前缀、40 位）。
  凭据由 GCM 管理，**仓库里、代码里、文档里都不许出现令牌本身**。
- **已失效**：`.workbuddy/credentials/.token` 里那枚旧的 fine-grained PAT（93 位）已经 401；
  "90 天轮换、到期某日"的旧口径按此作废 —— 将来轮换 = **重走一遍 GCM 授权**。
- **CI 状态取真值的通道**（每轮收尾要做，配方在 `docs/HANDOVER.md` §5.9）：
  `git credential fill`（stdin 喂 `protocol=https` + `host=github.com`）把令牌**只在内存里过一遍** →
  调 `https://api.github.com/repos/<owner>/<repo>/actions/runs?head_sha=<完整提交哈希>` →
  **只打印 run 号 / 状态 / 结论 / head_sha**；密文零回显、不落文件、不改 `git config`。
  三条实测坑：① **别加 `GCM_INTERACTIVE=never` 或 `GIT_TERMINAL_PROMPT=0`**，那样 helper 会不返回也不报错地挂死；
  ② 匿名访问私有仓库返回 **404**（不是 401），别读成"仓库不存在"；
  ③ **按 `head_sha` 查不到 run ≠ CI 失败** —— workflow 只跟 `main` / PR，
  随标签推上去的主体提交根本没有 run，台账要写"未触发"，不许推断成败。
- 取真值的脚本**一次性**放 `.tmp/` 随清理收走，**不升进 `scripts/`**（读凭据的工具进仓 = 多一条长期维护的攻击面）；
  **日志别落到 `.tmp/`**（会被 `cleanup.py` 自己扫走，见 §六第 3 条），落到 `.evidence/` 这类受保护区。
- 本轮还确认：会话里若挂了 GitHub MCP，它的工具面**不含 workflow 状态**（只有 commit / pr / issue / release 那类）——
  下一格 CI 状态仍以 REST 配方为准。

## 六、这个仓库现在最难缠的三件事（不是 bug，是环境的性质）

1. **`verify:pack` 的"本机锁"**：`electron-builder` 解 Electron 运行时是"写 `win-unpacked.tmp` → rename 成正式目录"，
   而本机常驻进程（监视 / 索引 / 实时扫描那类）会在 rename 那一刻握着 `.tmp` 里的 `resources/default_app.asar` ⇒ `EPERM`。
   **同一条因果被实测改口三次**，最终结论（全部有实测撑着，见 `review/REVIEW-LOG.md` 复核 092 / 093）：
   · 与目录叫什么名字**无关**（全新空目录第一次打照样 EPERM）；
   · 与"工作区根之内/之外"**相关但不决定**（之外 2 试全绿、之内 6 试 4 红 2 绿）；
   · **等待不是药**（失败留下的那只 asar 32 分钟后仍 EBUSY；原地重试每次都先 `unlink` 上一回残骸，
     于是第二次尝试根本没走到 rename，还会转成联网重取的 `ETIMEDOUT`，单次烧掉 199 秒）；
   · 现在最好的解释是**竞态窗口**：绿的两次首attempt 都慢（30.0s / 60.4s），红的几次只用 7.5–8.0s。
   **脚本的做法**：不原地盲等（最多 2 次 / 只等 5s）+ 失败当下用 `lockProbe` 试一次"给那只 asar 改名"，
   把"句柄此刻还在不在"打进日志；**操作口径：红了就直接重跑一次**（重跑用全新目录、不碰残骸），
   连红两把就按"这台机器此刻验不了打包产物"记账。
   **不要**把这类红写成产品缺陷，也**不要**为了变绿放宽判定。
2. **五只删不掉的 116KB 残骸**（`apps/desktop/release/pack-*` 里各一只 `win-unpacked.tmp`，加仓库外一只）：
   同一把锁导致的，登记在 `docs/TRACK-ROADMAP.md` 的 **T69**，处置方式（等松手 / 手工删 / 换暂存位置）要所有者点头。
3. **清理脚本会吃掉自己的证据**（T70，已修）：`cleanup.py` 原来把"全项目任何 0 字节文件"当垃圾，
   于是把**自己刚写的日志**搬进了回收站（shell 重定向先建空文件、脚本最后才打印）。
   现在的判据：0 字节**只在临时区里才算垃圾**，区外**只报不动**（报告单列一行），`.evidence/` 整区不进遍历。
   这条同时进了机械判据（护栏的"清理脚本只把临时区里的空文件当垃圾"那一条 + 注入自检对应的一处）。

## 八、写代码与写台账的硬规矩（踩过的坑，不写会复发）

- **静默失败是头号禁区**：任何"跳过 / 吞掉 / 兜底"都要在日志里说一句话，并说清**为什么可以这样**。
- **注释里写因果必须带证据**，没证据就写"未证"或者不写。
  （R34 把一句没被证伪过的话抄进注释 ⇒ R35 同一句错话有三个住处，逐处才扫干净。）
- **更正一处虚构后，grep 同一符号名扫全部引用处**（半条错话最难发现）。
- **新写一条断言/护栏，先校准"它能不能红"**；本仓的机器化做法：护栏加进 `scripts/check-docs.mjs`，
  同时在 `scripts/verify-docs-check.mjs` 加一处**注入用例**，跑一次看它红不红。
  假锁的常见形态（都实测撞过）：needle 被同一行的运行期文案自引用喂饱（**判据要认调用形状，不认名字**）、
  诊断文本拼在会被截断的位置（`fail()` 的 detail 有 900 字上限 ⇒ **取证要放最前**）、
  检查器自己做归一化、锁读原文被注释喂饱、时限锁没走到那段代码、判据架在恒真属性上。
- **变异**：只在**已提交的干净基线上**跑；锚点必须**恰好命中 1 次**；注入失败**必须当红灯**；
  还原不许用 `git checkout --`；新变异编号从 **M314** 起（清单条目数以 `review/mutations.json` 为准）。
- **e2e 加步骤只能往"关闭应用"之前追加**（插在中间会让台账里"第 N 步"的红绿证据错位）。
- **删除一律走 `cleanup.py`**（移进 `.trash/<批次>/`，30 天可反悔，绝不直接删）；
  测试与临时数据只落项目内 `.tmp/`，**不写系统盘**。
- **Markdown**：表格单元格**不能带换行**（整行必须自封闭；护栏会咬）；
  含反引号或 `${}` 的内容用编辑工具写文件，不要塞 heredoc。
- **行尾**：Windows 上脚本以文本模式写文件会把整批改写成 CRLF，而 `git diff --numstat` 看不出来 ⇒
  **按字节核行尾**（护栏里有现扫）。
- **中文路径**：`electron-builder` 一类工具在本机会把仓库路径编码成乱码（`俱佳agent` → `¾ã¼Ñagent`），
  导致报错文本误导排查 ⇒ 新机械判据/文案里尽量用相对说法，别把本机绝对路径写进代码与配置
  （护栏第 9 条：代码与配置里不许有本机绝对路径；活文档里不许有用户主目录）。
- **不要写"独立完成"**：这是 vibe coding 出来的项目（毕设除外）；**未收尾的事不许说"已完成"**。

## 十、目录搬到 `D:\Github项目\jujia-agent` 这一格（**已执行并验证**，2026-10-20）
