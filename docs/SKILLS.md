# 技能（Skills）：按需查阅的说明书

技能就是**一个目录 + 一个 `SKILL.md`**。它解决的是同一类问题：
"我希望 Agent 每次做某件事时都按我的步骤来，但我不想把这些步骤每轮都塞进对话。"

- 系统提示里只放**清单**（技能名 + 一句话描述）；
- 模型真正要用的那一刻，才用 `load_skill` 把完整正文读进来。

这样做有两个好处：**省 token**，而且"模型到底加载了哪个技能"在工具调用记录里**看得见**。

---

## 一、放哪里

| 位置 | 作用范围 | 优先级 |
|------|----------|--------|
| `<数据目录>/skills/<技能名>/SKILL.md` | 你这个用户的所有工作区 | 低 |
| `<工作区>/.jujia/skills/<技能名>/SKILL.md` | 只在这个工作区生效 | **高**（同名时覆盖用户级） |

数据目录在「概览」页可以看到（Windows 默认 `%APPDATA%\JujiaAgent\JuJiaData`）。
技能目录**每次发消息前重新扫描**，所以新增/修改技能后**不需要重启应用**。

---

## 二、`SKILL.md` 长什么样

```markdown
---
name: release-check
description: 发版前的自查清单（版本号、变更记录、标签、构建）
---

# 发版前自查

按顺序做，任何一步不通过就停下来告诉用户：

1. 读 `package.json`，确认版本号已递增；
2. 读 `CHANGELOG.md`，确认本版有对应条目；
3. 跑 `npm run typecheck`、`npm run lint`、`npm run test`，全绿才继续；
4. 提醒用户：打标签与推送需要他本人确认。
```

### frontmatter 规则（只有两个字段是必需的）

| 字段 | 必需 | 说明 |
|------|------|------|
| `name` | ✅ | 技能名。只能用**小写字母、数字、`-`、`_`**，且以字母或数字开头 |
| `description` | ✅ | 一句话说明"什么时候该用它"。**渐进披露全靠它** —— 没有它，模型无从判断该不该加载 |
| 其它字段 | — | 会被读取但当前不影响行为（预留给将来用） |

正文（第二个 `---` 之后的部分）就是给模型看的说明书。写得越具体、越有可执行的步骤，效果越好。

---

## 三、边界（会被拒绝并告诉你原因）

- `name` 不合规、缺 `description`、正文为空 → **跳过**该技能；
- `SKILL.md` 超过 64KB → 跳过（技能是说明书，不是数据仓库）；
- 同名技能在多处存在 → 按优先级取一个，其余记入"跳过"清单（**不会静默消失**）；
- 清单最多列 40 个技能、描述最多 200 字，超出会截断并注明还有多少个。

被跳过的技能在加载摘要里能看到原因 —— 这也是"我明明装了它怎么没生效"的答案所在。

---

## 四、为什么清单是排好序的

技能清单会并进系统提示。它**按名称排序、不含路径也不含时间**，
所以只要你的技能集合不变，这部分文本就**逐字节相同**。

这不是洁癖：系统提示是模型缓存的前缀，前缀一变，缓存全失效，
**每一轮都要重新处理整段上下文**，又慢又贵。有测试钉住这条性质（同样的目录 → 同样的文本）。

---

## 五、和「钩子」的分工

| | 技能（Skills） | 钩子（Hooks） |
|---|---|---|
| 谁执行 | **模型**（按说明书自己动手） | **你的程序**（在固定时机被调用） |
| 何时生效 | 模型决定要用它时 | 事件发生时（工具前后、审批时、回合结束…） |
| 能否拒绝操作 | 不能（只是说明书） | **能**（退出码 2 = 拒绝） |
| 典型用途 | 流程、规范、领域知识 | 兜底规则、审计、自动修正 |

一句话：**技能教模型怎么做，钩子保证它必须这么做**。两者的契约细节见 `docs/HOOKS.md`。
