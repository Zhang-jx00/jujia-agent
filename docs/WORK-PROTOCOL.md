# Qoder 工作协议（定稿 · 自包含）

> **这份文件是什么**：项目所有者在整个开发过程中提出的全部要求，加上项目自己踩坑后固化的规矩，
> 合并成一份**可逐条对照自查**的协议。它不是"建议"，**每一条都有出处**（留痕见
> `review/REVIEW-LOG.md`、`docs/TRACK-PLANS.md`、`docs/HANDOVER.md` §5）。
>
> **怎么用**：① 开发方**每次提交前逐条自查**；② 复核方逐条核查，发现偏离按
> **「问题 / 原因 / 影响 / 修改建议」** 四段输出，经所有者确认后才继续后续工作；
> ③ 与本文件冲突的旧表述一律以本文件为准，但**已被机器检查的口径改动的，改检查不改文档**。
>
> 最后核定：2026-09-24（所有者与复核方共同定稿）。

---

## 一、流程纪律

1. **每阶段收尾复核两遍，全部落 `review/REVIEW-LOG.md`；未记录 = 未复核。**
   - **第一遍 · 状态与一致性**：git 状态与标签一致 → `npm run check:docs` → 目录整洁 → 忽略规则 → 依赖健康 → 门禁实跑；
   - **第二遍 · 对抗性与运行时**：至少 1 条**变异测试** + 1 条**端到端异常路径实验**
     （数据损坏 / 断流 / 权限拒绝 / **红绿对照**）+ 静默失败嗅探；
   - 发现按「**编号 / 严重度 / 发现方式 / 处置 / 验证证据 / 状态**」登记；
     **无未处置的「严重 / 中」才允许进入下一阶段**。
2. **提交顺序（有讲究，勿调换）**：
   先写 CHANGELOG 条目 → 实现与测试 → **版本号先改** → 全门禁（含图形类）→ 提交（中文说明）→
   `mut`（**仅干净基线**）→ 打标签 → push → `git ls-remote` 核对远端 SHA → 台账 → `cleanup.py --apply`。
3. **收尾清理**：`cleanup.py` 预览 → `--apply`（入 `.trash/` 保留 30 天，**绝不直接删**）；任何删除先列清单核实。
4. **变异测试禁忌**：只在**已提交的干净基线**上做；**禁止用 `git checkout -- <file>` 还原未提交文件里的变异**；
   锚点必须**恰好命中 1 次**；**沙箱删除配额耗尽时绝不跑变异**；
   "无法运行"**单独成类、不计入被拦住**；逃逸就**补测试**，**不许放宽断言凑绿**。

## 二、真实性（所有者会抽查）

5. **绝不假称完成**：没做的写没做，跑不成的写跑不成；未跑成的门禁如实标注，**不声称全绿**。
6. **来源宁缺勿滥**：缺合格来源就留空并写明原因；**绝不编造 URL / 论文编号 / 课程名 / 版本号**。
7. **每轮开发前联网核实第三方信息**（模型版本 / API / 依赖 / 最佳实践），文档注明来源 URL + 核实时间；
   发现项目内记录过时**立即修正并留痕**。
8. **不拿旧信息冒充最新**；查不到就写"查不到"。
9. **统计一律用脚本**（`count_coverage.py` / `gen_matrix.py` / `check:docs`），不采信口头汇总数字；
   **数字只写一处**（`docs/PROGRESS.md`），其余位置写"以脚本 / 文件为准"。
10. **检查器必须证明会咬**：改规则必配**注入式自检**（`npm run check:docs:selftest`）；
    测试的**被测差异必须在取值上真实存在**。

## 三、对外表述与命名

11. **全仓（含源码注释、文档、脚本）不得出现参考项目名称或"借鉴 / 对标"表述**（哈希断言在岗）；
    学到的东西内化成"我们为什么这样做"；研究痕迹只留私有目录（`§5.10` 与 `.workbuddy/research/` **永不入库**）。
12. **提交说明一律中文**（无英文前缀），正文**不得含被禁字样**（含 `cmd.exe` 这类会被扫描器误判的字面量）。
13. **轨道计划记录规则**：十条轨道（回归 / 铺设 / 扩容 / 拓展 / 加固 / 升级 / 优化 / 规整 / 排查 / 接驳），
    判据见 `docs/TRACK-PLANS.md`；CHANGELOG 标题 `[vX.Y.Z-轨道N]` + 正文首行写归属；
    编号连续不复用；**绝不改写已推送的 git 历史与标签**。
14. **里程碑编号唯一权威 = `docs/TRACK-ROADMAP.md` §一（M1–M23）**；
    废弃写法禁用（`M0` / `M5a` / `M5b` / `M6b` / 把 `P5` 当模块号 / "钩子四类"）。

## 四、结构与整洁

15. **分目录归档**：知识进 `knowledge/`、规划进 `docs/`、复核与排查进 `review/`，不另起散乱目录；
    **新文件必须挂进导航或白名单**（孤儿文件 / 悬空引用检查在岗）。
16. **收尾标准**：无临时文件残留、无本机绝对路径（断言在岗）、无 TODO/FIXME 堆积、`.gitignore` 完整。
17. **测试与临时数据不写系统盘**：一律落项目内 `.tmp/`；e2e 数据隔离到唯一临时目录；
    并定期清理无用临时文件 / 死代码 / 旧目录，**但要做好记录**。

## 五、安全与权限

18. **每个有副作用的动作都要用户点头**；权限判定用**确定性规则**；
    `deny` / `ask` **绝对生效**（连 `bypassPermissions` 也让路）。
19. **密钥不进渲染层、不进模型上下文、不进任何聊天与提交**；
    凭据只放 `.workbuddy/credentials/`（仓库外）；fine-grained token **90 天轮换制**（到期 401 = 正常轮换）。
20. **数据默认不出本机**；引入出站 / 远程能力前必须先解决与该定位的冲突（M20 / M21 冻结中）。
21. **静默失败是头号禁区**（S1 与 G-8 都源于此）；"暂不做 / 降级"的能力如实标注，
    **不留死代码、不悄悄恢复**。

## 六、验证（所有者零人工测试）

22. **所有验证自动化**；界面操作**必须 e2e**；**不许以"请手动验证一下"收尾**。
23. **门禁全绿才打标签**；CI 与本地门禁的差异如实标注；**先改版本号再跑图形类门禁**。
24. **测试写法红线**：排序类用例的输入顺序要与期望相反；被测差异必须在取值上真实存在；
    源码扫描**先剥注释**、断言串**含完整上下文**；抽出纯函数后要加"**真的在用它**"的接线锁。
25. **敏感信息扫描的方法论**：**不信任环境变量做判据**（`$USERNAME` 实测只有 1 个字符）；
    **大小写不敏感 + 变体串**；**报告数量与文件清单、不回显敏感值本身**；
    并区分三类对象（GitHub 账号名 / 本机账户名 / 仓库路径）—— 处置方式完全不同。

## 七、持续学习

26. **每轮沉淀知识**：新坑进 `knowledge/cards/`（编号递增）、新技术事实注明来源与核实时间；
    新里程碑动工前对应知识簇要有据可依（M9→S9 · M10→S10 · M11→S11）；
    **本轮确无新增则在台账写明**。
27. **选型留痕**："为什么用现在这个做法、替代了什么旧做法"落到文档；
    重要交付物做**多遍复查**（先例：交接文档三遍复查）。
28. **重要取舍要所有者拍板**：影响能力边界、产品定位、安全语义的决定，**先报备后动手**；
    已经自作主张采用的口径，要在下一轮回执中**单独标出请求确认**。
