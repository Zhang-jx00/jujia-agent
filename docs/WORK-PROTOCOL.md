## 一、流程纪律

1. **每阶段收尾复核两遍，全部落 `review/REVIEW-LOG.md`；未记录 = 未复核。**
   - **第一遍 · 状态与一致性**：git 状态与标签一致 → `npm run check:docs` → 目录整洁 → 忽略规则 → 依赖健康 → 门禁实跑；
   - **第二遍 · 对抗性与运行时**：至少 1 条**变异测试** + 1 条**端到端异常路径实验**
     （数据损坏 / 断流 / 权限拒绝 / **红绿对照**）+ 静默失败嗅探；
   - 发现按「**编号 / 严重度 / 发现方式 / 处置 / 验证证据 / 状态**」登记；
     **无未处置的「严重 / 中」才允许进入下一阶段**。
2. **提交顺序（有讲究，勿调换）**：
   先写 CHANGELOG 条目 → 实现与测试 → **版本号先改** → 全门禁（含图形类）→ 提交（中文说明）→
   `mut`（**仅干净基线**）→ 打标签 → push → `git ls-remote` 核对远端 SHA → 台账 → `cleanup.py --apply`。
   **推送一类命令禁止接管道**：`git push ... | tail` 的退出码是 `tail` 的，失败会被读成成功（实测差点误报"已推送"）。
   要看输出就**重定向到文件再读**，或先 `set -o pipefail`。无论哪种，**`git ls-remote` 核对那一步永远不许省** ——
   它是这条链上唯一能证伪"我以为推上去了"的东西。
3. **收尾清理**：`cleanup.py` 预览 → `--apply`（入 `.trash/` 保留 30 天，**绝不直接删**）；任何删除先列清单核实。
4. **变异测试禁忌**：只在**已提交的干净基线**上做；**禁止用 `git checkout -- <file>` 还原未提交文件里的变异**；
   锚点必须**恰好命中 1 次**；**沙箱删除配额耗尽时绝不跑变异**；
   "无法运行"**单独成类、不计入被拦住**；逃逸就**补测试**，**不许放宽断言凑绿**。

## 二、真实性（所有者会抽查）

5. **绝不假称完成**：没做的写没做，跑不成的写跑不成；未跑成的门禁如实标注，**不声称全绿**。
6. **来源宁缺勿滥**：缺合格来源就留空并写明原因；**绝不编造 URL / 论文编号 / 课程名 / 版本号**。
7. **每轮开发前联网核实第三方信息**（模型版本 / API / 依赖 / 最佳实践），文档注明来源 URL + 核实时间；
   发现项目内记录过时**立即修正并留痕**。
8. **不拿旧信息冒充最新**；查不到就写"查不到"。
9. **统计一律用脚本**（`count_coverage.py` / `gen_matrix.py` / `check:docs`），不采信口头汇总数字；
   **数字只写一处**（`docs/PROGRESS.md`），其余位置写"以脚本 / 文件为准"。
10. **检查器必须证明会咬**：改规则必配**注入式自检**（`npm run check:docs:selftest`）；
    测试的**被测差异必须在取值上真实存在**。

## 三、对外表述与命名

11. **全仓（含源码注释、文档、脚本）不得出现参考项目名称或"借鉴 / 对标"表述**（哈希断言在岗）；
    学到的东西内化成"我们为什么这样做"；研究痕迹只留私有目录（`§5.10` 与 `.workbuddy/research/` **永不入库**）。
12. **提交说明一律中文**（无英文前缀），正文**不得含被禁字样**（含 `cmd.exe` 这类会被扫描器误判的字面量）。
13. **轨道计划记录规则**：十条轨道（回归 / 铺设 / 扩容 / 拓展 / 加固 / 升级 / 优化 / 规整 / 排查 / 接驳），
    判据见 `docs/TRACK-PLANS.md`；CHANGELOG 标题 `[vX.Y.Z-轨道N]` + 正文首行写归属；
    编号连续不复用；**绝不改写已推送的 git 历史与标签**。
14. **里程碑编号唯一权威 = `docs/TRACK-ROADMAP.md` §一（M1–M23）**；
    废弃写法禁用（`M0` / `M5a` / `M5b` / `M6b` / 把 `P5` 当模块号 / "钩子四类"）。

## 四、结构与整洁

15. **分目录归档**：知识进 `knowledge/`、规划进 `docs/`、复核与排查进 `review/`，不另起散乱目录；
    **新文件必须挂进导航或白名单**（孤儿文件 / 悬空引用检查在岗）。
16. **收尾标准**：无临时文件残留、无本机绝对路径（断言在岗）、无 TODO/FIXME 堆积、`.gitignore` 完整。
17. **测试与临时数据不写系统盘**：一律落项目内 `.tmp/`；e2e 数据隔离到唯一临时目录；
    并定期清理无用临时文件 / 死代码 / 旧目录，**但要做好记录**。

## 五、安全与权限

18. **每个有副作用的动作都要用户点头**；权限判定用**确定性规则**；
    `deny` / `ask` **绝对生效**（连 `bypassPermissions` 也让路）。
19. **密钥不进渲染层、不进模型上下文、不进任何聊天与提交**；
    凭据只放 `.workbuddy/credentials/`（仓库外）；fine-grained token **90 天轮换制**（到期 401 = 正常轮换）。
20. **数据默认不出本机**；引入出站 / 远程能力前必须先解决与该定位的冲突（M20 / M21 冻结中）。
21. **静默失败是头号禁区**（S1 与 G-8 都源于此）；"暂不做 / 降级"的能力如实标注，
    **不留死代码、不悄悄恢复**。

## 六、验证（所有者零人工测试）

22. **所有验证自动化**；界面操作**必须 e2e**；**不许以"请手动验证一下"收尾**。
    **单测证明函数对，界面级才证明接上了**（2026-09-27 批复固化）：一条新能力若只在单测里绿过、
    没沿真实链路走过界面（e2e 或渲染层组件测试），就等于**没验证过** —— 本轮第一次在界面级真跑流式对话，
    当场掉出三个问题（种子不实、用量事件从来没上界面、上游卡死被显示成"已停止"）。
    渲染层组件测试用 jsdom + @testing-library，**只作 devDependencies，不碰运行时，也不加覆盖率门禁**。
23. **门禁分两档**（2026-09-29 复核 044）：**快档**（typecheck / lint / test / check:docs / e2e）**全绿才打标签**；**慢档**（smoke / perf / verify:pack / mut）在**阶段收尾与发版前**必跑全绿 —— 慢档验的是打包配置、启动行为、变异覆盖，不会每轮都变，每轮跑是成本与收益不匹配（清单以 `docs/PROGRESS.md` 为准）。CI 与本地门禁的差异如实标注；CI 与本地门禁的差异如实标注；**先改版本号再跑图形类门禁**。
24. **测试写法红线**：排序类用例的输入顺序要与期望相反；被测差异必须在取值上真实存在；
    **安全类断言必须双向**（复核 031 升格为通用范式）：断"危险的东西没进 DOM"的同时，
    必须断"那串源文本还在 / 那个语法确实被识别"。只测前一半，**"整块根本没渲染"会被当成通过** ——
    本质就是实验设计里的阴性对照 + 阳性对照，缺一个都会骗人（先例：G-8、N-1、P-3、P-5）；
    源码扫描**先剥注释**、断言串**含完整上下文**；抽出纯函数后要加"**真的在用它**"的接线锁。
25. **检索与扫描的方法论（含"查不到"怎么处理）**：**任何"我没搜到"都不等于"它不存在"** ——
    先排除三件事再下结论：① **路径找对了没**（先例：复核方在 `packages/agent-core/src/markdown/` 搜图片语法，
    实现在 `renderer/src/markdown/`，于是把"已实现"判成"没有"）；② 大小写与变体；③ 判据本身是不是残缺的
    （见下面敏感信息扫描那几条）。要断言"不存在"，必须给出**你搜了哪里 + 用什么模式**；
    被这样纠正时，按事实认错并补方法，不改口。
    **敏感信息扫描**：**不信任环境变量做判据**（`$USERNAME` 实测只有 1 个字符）；
    **大小写不敏感 + 变体串**；**报告数量与文件清单、不回显敏感值本身**；
    并区分三类对象（GitHub 账号名 / 本机账户名 / 仓库路径）—— 处置方式完全不同。

## 八、状态回传范式（复核 030 的 N-1 固化；`ipc/browser.ts` 那条锁注释是可复制的样板）

29. **凡是「invoke 返回值 + `*_STATE_CHANGED` 广播」双通道往界面送同一个状态的，响应体里的状态一律现读**
    （`browser.state()` 这种当场取），**禁止把处理过程中取到的快照当结论返回**，并用接线锁禁掉
    `state: result.state` 这类形状。原因：那份快照的新旧**取决于返回路径上隔了几个 `await`**，
    而 `await` 只会越加越多 —— 本轮就是多加了一次配置写入，导致"被拦"广播先到、旧快照后到并盖掉它，
    界面把"拦截其实生效了"显示成"点了没反应"（N-1，e2e 第 15 步当场抓出）。
    同一形状的隐患在任何"返回值 + 广播"的通道上都成立（MCP / 终端 / 浏览器 / 以后的 git）：
    要么现读，要么给状态带序号做比较，**不要指望调用顺序永远不变**。
    **收紧判据（所有者与复核方 2026-09-26 定）**：本条**不升级为"全局给状态加序号"** ——
    为一个已被形状锁钉死的竞态去把全部通道 + preload + 渲染层改成带序号的请求-响应，
    改动面与收益不成比例，还会制造新的兼容负担。只有当某条通道**同时满足**
    ① 双通道（invoke 返回值 + 广播）② 该操作会写状态 ③ 响应路径上还有其它 `await`，
    **并且再次出现实际时序问题时**，才对该通道单独加序号。规则是活的，机制不用预支。

## 九、工具与脚本纪律（2026-09-29 复核 041 后定；两条都是"踩了才知道边界在哪"）

30. **写文件一律用编辑工具；脚本只做"读与跑"，不做文本生成。**
    *为什么升级*：原口径是"内容里有反引号或 `${}` 才走编辑工具"——边界太窄，没覆盖**转义**这一整类。
    复核 041 的 R-4：用 shell heredoc + 脚本往 TS 里写含 `
` 的字符串，连续两次把**真换行**写进了
    字符串字面量（`split('
')` 变成跨行的非法字面量），typecheck 报 `Unterminated string literal`。
    *做法*：要改文件 → `Read`/`Edit`/`Write`；脚本只允许做"读文件、跑命令、统计与校验"。
    写坏一次要花两倍时间修，还会让人误以为"是产品坏了"。

31. **凡枚举"现状清单"的锁与校验，一律现扫，不写死清单。**
    *为什么*：同一个坑已经踩到第三次（H-4 → K-3 → M19 复核 041 的 R-1）：接线锁的模块清单写死后，
    新增 `ipc/pdf.ts` 整块**离开扫描范围**——锁照样绿，而它本该覆盖的通道根本没被检查；
    报出来的"缺 PDF_OPEN"看着像漏注册，实际是锁失焦。**失焦的锁比没有锁更坏**：它给人覆盖的错觉。
    *做法*：目录现扫（`readdirSync` + 排序）或从常量表派生；写死清单只允许出现在"清单本身就是被测对象"
    的场合，且必须配一条反向断言证明它不会悄悄漂。
