## 〇、先说结论：这一轮的核心不是"画布"，是"节点里的执行必须与对话走同一条链路"

PLAN 的 M9 验收里最关键的一条是"3 类节点连成工作流并**成功执行**、节点状态回写正确"。
拖拽/连线/对齐是纯界面；真正会出事的是**执行**：一个"工具节点"在图里跑起来，它过没过权限门？
一个"提示词节点"调模型，走哪条连接、记不记用量、能不能被停下？
本仓在这两件事上都已经有**唯一正确的通道**（工具 = `runTool` + 权限门；模型 = `agent-loop`），
所以 M9 的铁律是：**图只是编排，执行一律复用既有链路，绝不新建第二套执行器。**

## 一、范围切分（M9a / M9b）

| | M9a（本轮） | M9b（另报备） |
|---|---|---|
| 画布 | 节点/连线/选中/拖拽/视图缩放平移/成环与类型校验/网格吸附/右键与双击建节点 | 对齐辅助线与等距分布、命令面板、节点折叠 |
| 节点类型 | **提示词节点**（调模型）· **工具节点**（调内置工具） | 子代理节点、条件/循环等控制流 |
| 执行 | **整图拓扑执行**（DAG 顺序）、逐节点状态回写、可中止 | 并行分支、局部重跑、断点续跑 |
| 持久化 | 图 JSON + version 信封（`json-store` 同源）+ 迁移骨架 + 导入/导出 | 多图管理、模板库 |
| 文档 | `docs/LINKAGE-M9.md`（接驳契约，批复要点④） | — |

**为什么这么切**：PLAN 的验收要求"3 节点流程能执行"，所以整图执行必须在第一轮；
而"对齐辅助线 / 命令面板"是体验项，不影响正确性 —— 与 M19a/M19b 同一个切法。

## 二、执行怎么接（批复要点①：不许自建执行器）

| 节点 | 走哪条链路 | 判档 | 说明 |
|---|---|---|---|
| 提示词节点 | **`agent-loop` 的同一入口**（与对话页同一个 provider 调用层） | 模型调用本身不是"有副作用的动作"，照旧不额外加门；但要**选连接、计用量** | 图级设置里选"这次跑哪条连接"；**不复用某个会话** —— 图有自己的运行记录 |
| 工具节点 | **`runTool(...)`**（与对话/手动执行**同一个注册表 + 同一个权限门**） | 读类不问 / 写类软 ask / 执行类硬 ask，与今天一字不差 | 图执行期间的审批弹窗照常出现；用户拒绝 → 该节点状态 = **被拒**（不是静默跳过） |
| 子代理 / 控制流 | — | — | M9b |

**新写的只有"编排"**：拓扑排序、逐个调度、状态机（待跑/在跑/成功/失败/被拒/被中止）、取消传播。
"执行一个节点"这件事永远落到上面两条通道之一 —— 这条用**接线锁**钉住：图执行模块里
不许出现 `fetch(`、不许构造 provider、不许直接碰 `node:fs`。

## 三、数据面（批复要点②）

- 存储：`<数据根>/canvas/<graphId>.json`，走 **`json-store`**（同一个原子写 + 版本信封 + `.bak` 回退 + 损坏隔离）——
  不另造一套存储。
- schema：`packages/shared-ipc/src/canvas-graph.ts`（zod、`.strict()`）：
  `{ version, nodes[{id, kind, x, y, config}], edges[{id, from, to, fromPort, toPort}], viewport }`。
- **迁移骨架**：与 json-store 的 `migrate` 选项同源；本轮只有 v1，但迁移入口与测试都在
  （造一个"v0 旧数据"的用例证明骨架真的会跑，而不是写着好看）。
- 回退：不额外做双写 —— json-store 自带 `.bak` 与损坏隔离；另外给"导出 JSON"，
  坏图能被用户救出来（导出是纯读，不打扰）。

## 四、有界（批复要点③）

| 对象 | 上限（推荐） | 超限行为 |
|---|---|---|
| 节点数 | 200 | 拒绝新增并说明 |
| 边数 | 400 | 同上 |
| 单节点配置（提示词/参数） | 8 KB | 截断并如实标注 |
| 图文件大小 | 2 MB | 拒绝保存/加载并说明 |
| 单次执行步数 | 50 个节点 | 中止并说明（防"图里放了长链"把界面拖住） |
| 单节点模型调用 | 沿用既有 `maxTurns` / 超时口径 | 不新造数字 |

上限集中在 `shared-ipc` 的常量表（与 M19 的 `limits.ts` 同一做法，便于将来调）。

## 五、打包后是否仍成立（批复要点⑤）

M9 会引入：一个新依赖（画布库，见 §六）、一个新 chunk、可能的新 IPC 通道（图 CRUD）。
逐条对照：
- **依赖**：`@xyflow/react`（MIT，unpacked 1.2MB，**带 zustand / classcat / @xyflow/system 三个传递依赖**）
  —— 装完跑 `license:check` 归类 §A，体积记 `PERF-BUDGET`；
- **chunk**：画布页与 M19 一样 `lazy()`，首屏不受影响（**用量实测**，不许"应该没事"）；
- **通道**：图 CRUD 走主进程 + `.strict()` 契约；**执行不新增通道**（复用 `TOOL_RUN` 与对话链路）；
- **打包后验证**：见 §七 —— 本轮要把"打包产物验证"至少做出最小一条。

## 七、打包产物验证（复核 042 的系统性建议，排在 M9 之前或并行）

**最小一条先做**：`npm run verify:pack` —— 用 `electron-builder` 的 **dir 目标**（不签名、不出安装包）
构建一次，再用 e2e 那套 Playwright **驱动打包产物**跑三步：
① 启动；② 打开「文件」页签并展开树；③ 打开一份 PDF 看到页数。
**为什么必须有它**：本轮踩到的坑（`file://` 页面不许 `fetch` 本地文件）**只在打包产物里出现**，
而现有全部门禁跑的都是 `out/` 的开发产物 —— 也就是说，"发出去才会坏"的那一类问题今天没有门禁能拦。

## 八、可测性与验收

- **纯函数层** `canvas-graph.ts`：DAG 校验（成环 / 重复边 / 悬空端口 / 类型不匹配）、拓扑排序、
  上限判定、迁移 —— 全部单测 + 变异（M71 起）。
- **接线锁**：图执行模块只经 `runTool` / agent-loop（不许出现 provider 构造、不许 `fetch(`、不许直接 fs）。
- **e2e**（追加 3 步，只能插在"关闭应用"之前）：
  1. 建 3 节点连成链 → 执行 → **磁盘真值**（图文件里状态被回写、执行记录 3 条）；
  2. 连成环被拒且提示明确（DAG 校验在界面与纯函数两层都拦）；
  3. 工具节点跑起来时**弹审批**（与对话同一条门）→ 拒绝 → 该节点状态=被拒（不是静默跳过）。
- **打包后验证**：§七 那三步。

## 九、本阶段不做（**时序界定 —— 不是"永久不做"**）

**M9a 不做 ≠ 永久不做**（§一 的 M9a/M9b 切分表已把其中一部分**排给 M9b**；旧措辞"明确不做"容易被读成永久，
2026-10-06 依复核意见改写）：**M9a 阶段不做** —— 控制流节点（条件/循环）· 并行分支 ·
局部重跑 / 断点续跑（**归 M9b**，且必须复用 `canvas-runner`，不许另写执行路径）· 模板库与多图管理（M9b 之后再议）·
画布内嵌浏览器/终端（另议）· 把图执行结果再喂回对话（那是另一条链路，要单独设计）。
**子代理节点的归口**：**M14**（多子 agent 编排）—— 画布侧只做"接线口"设计，真做等 M14 报备；
放入 M9b 会让"M14 做了一半"（归属不清）—— 此项归口**待复核方确认后**写入 M9b 报备。

## 九之二、批复追加的两条要求（复核 043 裁决①，已并入设计）

**(a) 流事件归属判别**：图执行产生的流事件（节点状态、输出增量）**也必须能区分归属** ——
这是 T5 "事件按会话分发"的推广：**任何新的"事件来源"都要有归属判别**，否则又会长出跨来源污染。
落地：图执行的事件带 `graphId` + `nodeId`，渲染层沿用 `belongsToSession` 那一套"读 ref 不读 state"的闸门，
并新增接线锁（同类断言：没有归属字段的事件不许进界面）。
（复核 043 原话："T5 stream-routing 的推广"。）

**(b) 图 JSON 里不得存 API Key**：只存 `connectionId`，密钥仍在 secret store ——
这是"密钥不进渲染层 / 不进模型上下文 / 不进任何聊天与提交"的延伸，**再加一条"不进可分享文件"**：
图 JSON 是能被导出与分享的，所以它里面出现 `apiKey`/`secret` 这类字段本身就是事故。
落地：`canvas-graph.ts` 的 schema `.strict()`（多一个字段就拒）+ 单测断言"带 key 的图存不进去"。
