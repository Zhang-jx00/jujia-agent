# M20–M22 决策备忘：「数据不出本机」与远程 / 云端能力的表述冲突

> **性质**：R16 的三件文书之三。**本备忘不改变任何现状** —— 在所有者拍板之前，
> **不动工 M20 / M21 / M22**（口径沿自 `docs/HANDOVER.md` §5.8，2026-10-04 立、2026-10-14 重述）。
> 用途：把冲突讲清、把选项摆齐、把"若做要先补什么"列成先决清单 —— **供一次拍板**。
> 关联：`docs/ARCH-CLOUD-IDE.md`（远景设计）· `docs/PRODUCT-GOAL.md` §2.1c · `docs/DESIGN-MULTIMODAL.md`（R14 先例）。

---

## 一、冲突是什么（原文对原文）

**现役表述**（三处落点）：

- `README.md` §隐私 4：「**数据不出本机是默认值，不是可选项。**…所有数据落在本机一个数据根目录里」；
  「不经过我们的服务器（本项目也没有服务器）」。
- `docs/HANDOVER.md` §1.1：「**本地单机优先**：不做云端账号体系、不做商业化；本地单机、无服务器中转。」
- R14 批复后的补充表述（`DESIGN-MULTIMODAL.md` §二）：「**除你主动发起的模型请求（文字 / 图片）外，
  数据不出本机；附件只发给当前连接的服务商。**」

**远景设计**（`ARCH-CLOUD-IDE.md`，2026-09-18 检索成文、尚未开工）：

- **M20** 远程主机接入：SSH / 出站隧道 + 首次指纹确认 + 凭据保管；
- **M21** 云端 agent worker：远端执行运行时（同一套工具层 + 工具链 harness + 证据回传）；
- **M22** 本地 / 云端调度：确定性路由 + 迁移（显式确认）+ 断点续跑。

**冲突点**：M20–M22 的定义就是**任务与工作区数据离开本机**（去到另一台机器上执行），
与"数据不出本机"的字面表述冲突；`SECURITY.md` 的出站表**没有对应类别**
（现有四类：模型 API / MCP 子进程 / MCP 自发起 / 浏览器 —— 远程主机与 worker 不在其中）。

## 二、一个关键区分（先说清，省得把两句话混成一句）

- **「不经过我们的服务器」**：M20–M22 与这句**不冲突** —— 目标是**用户自己的**主机
  （自己的 sshd 或自己的云机器），本项目仍然没有服务器、没有账号体系。
- **「数据不出本机」**：与这句的冲突**是真实的** —— 数据会去第二台机器。这不是把话说岔了，
  是能力边界真要扩。已有一次同形先例：R14 的图片输入（数据第一次离开本机）走的是
  **"先报备、所有者批复新表述、再动手"** 的流程 —— 本备忘就是 M20–M22 版的报备材料前身。

## 三、选项（供拍板；**推荐值加粗**）

| 选项 | 含义 | 代价 / 前提 |
|------|------|-------------|
| **A. 维持本地单机定位，M20–M22 不做** | 把"本机之外"**永久**划出产品边界；README / PRODUCT-GOAL / ARCH 三处把"未开始"改成"不做"，不再留悬念 | 放弃"长任务在别处活着"的能力；文档要一次性改口径 |
| **B. 做，但先修订表述（推荐）** | 新表述候选：「**默认不出本机；只有你显式接入自己的主机、并显式把任务迁过去时，数据才会去到那台主机。本产品没有服务器。**」+ SECURITY 出站表新增"用户自建主机"类别并如实标注 | 需要一次**表述批复**（照 R14 流程）+ 先决清单（§四）；实现体量大，跨多个批次 |
| C. 中间态：只做 M20（连得上） | 只做"接入自己的主机 + 浏览 / 执行"，不做 M21 worker 与 M22 自动调度 / 迁移 | 能力半截，"长任务活着"的原始动机兑现不了；将来多半还要回到 B，返工风险高 |

> 推荐 B 的理由：它是唯一**既保住远景、又不把现役表述说岔**的选项 —— 该模式已在 R14 上跑通过一次
> （新表述 + 落点一次改齐 + 界面把话说明白）。无论选哪个，**本备忘本身不构成对 M20–M22 的承诺**。

## 四、若选 B / C：先决清单（做之前必须先补，缺一不做）

1. **表述批复**（与停牌①同类：出站语义变更）—— README / SECURITY / HANDOVER 三处落点**一次改齐**，
   界面（迁移动作的确认文案）把"将上传什么"说明白；
2. **`SECURITY.md` 出站表扩展 + 补齐现状** —— 新增"用户自建主机"类别（拍板后随实现一起做）；
   **两处已过时的行已在 R16 先改准**（**更新检查**：点一次发一次、不带本机数据的 GET；
   **内置浏览器**：已交付，不再是"后续阶段"，补了"跨站被拦 / 下载取消"的口径；README 的"出网两处"同步改准）；
3. **三条设计律不可破**（`ARCH-CLOUD-IDE.md` §2.2）：**会话状态归 host · 远端连接一律出站 · 绝不允许匿名可达**；
4. **权限门永远在本机**（ARCH §4.4 已是设计，实现时必须落成接线锁 —— 远端 worker 无放行权）；
5. **凭据保管**：主机凭据只进 safeStorage 体系，不进模型上下文、不进图、不进聊天（既有铁律的延伸）；
6. **测试面**：远端类功能无法只靠本机单测 —— 先设计一台"**假远端**"（本地子进程扮演 host/worker），
   否则 CI 上没有可跑的验收面；
7. **打包与界面验证**：`verify:pack` 与 e2e 的覆盖方式先想好（打包版连"假远端"怎么验），
   照 `LINKAGE-M9.md` §五 的既有纪律；
8. **出站类功能的通用口径**：照"检查更新"那套（点一次发一次、无轮询、接线锁扫源码钉住"绝不自动"）。
