# 性能预算与实测记录（M18 / W7）

> **为什么要有这份文档**：性能如果只靠"感觉还挺快"，就不可能发现退化。
> 这里给出**预算**（硬指标）与**实测值**（来自 `npm run perf`，可随时复跑回归）。
>
> ## ⚠️ 采样方法（2026-09-21 因误判而固化，务必遵守）
>
> 本文件曾记录过一条"启动性能单调上升（589 → 709 → 903ms）"的**回归信号** ——
> **该结论已被证伪并撤销**。原因是**采样方法错了**：
> 那三次采样分别紧跟在构建 / 安装 / 测试之后执行，**机器负载逐步累积**，
> 于是数字逐步变大，被误读成"代码在变慢"。
>
> **正确做法**：
> 1. **在机器空闲、连续跑 3 次以上**再下结论；单次采样**不可比**；
> 2. 不要把性能采样安排在大构建/安装/测试**之后**；先让它空闲几秒；
> 3. 报告时给出**多次采样的分布**（最小值 ~ 最大值），而不是挑一个数；
> 4. 只有**同一负载状态下**的多次采样才具备可比性。
>
> **改正后的实测（2026-09-21 空闲状态连续 3 次）**：
> `562ms` · `632ms` · `536ms` —— 均在同一水平波动，**未发现回归**。

## 一、启动性能（冷启动，实测打点）

命令：`npm run perf`（构建后真实启动 Electron，由渲染层首帧回报，打印时间线后退出）

| 阶段 | 打点 | 预算 | 实测（2026-09-21 连续 3 次） |
|------|------|------|-------------------|
| 主进程起点 | `main:start` | — | 0ms |
| 窗口创建 | `main:window-created` | < 600ms | ~200–280ms |
| 渲染层首帧 | `renderer:first-paint` | **< 1000ms（可交互）** | **536 / 562 / 632ms** |
| 合计 | — | **< 1500ms（冷启动）** | **同上** ✅ |

> 判定：`npm run perf` 会自行比对预算，超预算则以 **非零退出码**结束（可直接接入 CI）。
> 时间线的采集点是真实的（主进程 `Date.now()` + 渲染层挂载后的 `requestAnimationFrame`），
> 不是估算值。

## 三、W7 落地的四件事

1. **启动性能埋点 + 实测**：新增 `main/perfMark` 时间线与 `IPC.PERF_FIRST_PAINT`，
   渲染层挂载后回报首帧；`npm run perf` 打印时间线并做预算判定（可接 CI）。
2. **delta 合批**：流式期间模型每秒可能推几十次增量，原先每次都 `setState` → 高频重渲染；
   改为**先入缓冲区、用 `requestAnimationFrame` 每帧只刷一次**，并在卸载时清理 rAF 句柄。
3. **长会话窗口化**：默认只渲染最近 120 条气泡，更早的用「显示更早的 N 条」按钮按需展开
   （上万个 DOM 节点是滚动卡顿的主因）。这是**不引入依赖**的过渡方案，
   完整虚拟列表（react-window）留待后续。
4. **Tab 懒加载**：连接页、对话页、外观页、终端页都不在首屏，改为 `React.lazy` + `Suspense`，
   首屏只加载概览与权限弹窗；懒加载失败有骨架屏兜底，不会白屏。

## 四、2026-09-21 首屏依赖瘦身（attempted，影响有限但结果真实）

**动机**：怀疑 `App.tsx` 运行时 import `@jujia/ui-tokens` 把库拉进首屏 chunk、拖慢首帧。

**改动**：`App.tsx` 改为**只做类型导入**（编译后擦除），启动时的外观解析与 CSS 变量注入
改为 **动态 `import('@jujia/ui-tokens')`**；`themePack` 状态改为 `ThemePack | null`，
外观页在解析完成前显示骨架屏。

**实测效果（客观数据）**：
| 指标 | 改前 | 改后 |
|------|------|------|
| 主 chunk | 660KB | **652KB** |
| 主 chunk 内 `bubbleShape` 出现次数 | 6 | **0** |
| 主 chunk 内 `default-dark` 出现次数 | 1 | **0** |
| ui-tokens | 混在主 chunk 里 | **独立 12KB chunk（懒加载）** |

**如实评价**：改动**确实生效且可验证**（ui-tokens 已不在首屏路径），
但它**只占约 8–12KB**，因此**不是**此前那个"回归"的原因 —— 而那个"回归"本身**并不存在**（见文首）。
保留该改动的理由：首屏不该加载外观模块，这是**结构性正确**的依赖划分，
也让首屏 chunk 少了 8KB 与一次同步解析。
