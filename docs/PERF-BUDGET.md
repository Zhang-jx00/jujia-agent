# 性能预算与实测记录（M18 / W7）

> **为什么要有这份文档**：性能如果只靠"感觉还挺快"，就不可能发现退化。
> 这里给出**预算**（硬指标）与**实测值**（来自 `npm run perf`，可随时复跑回归）。
> **最新实测**：2026-09-20 · `npm run perf` → **PERF OK**

---

## 一、启动性能（冷启动，实测打点）

命令：`npm run perf`（构建后真实启动 Electron，由渲染层首帧回报，打印时间线后退出）

| 阶段 | 打点 | 预算 | 实测（2026-09-20） |
|------|------|------|-------------------|
| 主进程起点 | `main:start` | — | 0ms |
| 窗口创建 | `main:window-created` | < 600ms | **195ms** |
| 渲染层首帧 | `renderer:first-paint` | **< 1000ms（可交互）** | **466ms** |
| 合计 | — | **< 1500ms（冷启动）** | **466ms** ✅ |

> 判定：`npm run perf` 会自行比对预算，超预算则以 **非零退出码**结束（可直接接入 CI）。
> 时间线的采集点是真实的（主进程 `Date.now()` + 渲染层挂载后的 `requestAnimationFrame`），
> 不是估算值。

## 三、本轮(W7)落地的四件事

1. **启动性能埋点 + 实测**：新增 `main/perfMark` 时间线与 `IPC.PERF_FIRST_PAINT`，
   渲染层挂载后回报首帧；`npm run perf` 打印时间线并做预算判定（可接 CI）。
2. **delta 合批**：流式期间模型每秒可能推几十次增量，原先每次都 `setState` → 高频重渲染；
   改为**先入缓冲区、用 `requestAnimationFrame` 每帧只刷一次**，并在卸载时清理 rAF 句柄。
3. **长会话窗口化**：默认只渲染最近 120 条气泡，更早的用「显示更早的 N 条」按钮按需展开
   （上万个 DOM 节点是滚动卡顿的主因）。这是**不引入依赖**的过渡方案，
   完整虚拟列表（react-window）留待后续。
4. **Tab 懒加载**：连接页与对话页不在首屏，改为 `React.lazy` + `Suspense`，
   首屏只加载概览与权限弹窗；懒加载失败有骨架屏兜底，不会白屏。
