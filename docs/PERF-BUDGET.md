> ## ⚠️ 采样方法（2026-09-21 因误判而固化，务必遵守）
>
> 本文件曾记录过一条"启动性能单调上升（589 → 709 → 903ms）"的**回归信号** ——
> **该结论已被证伪并撤销**。原因是**采样方法错了**：
> 那三次采样分别紧跟在构建 / 安装 / 测试之后执行，**机器负载逐步累积**，
> 于是数字逐步变大，被误读成"代码在变慢"。
>
> **正确做法**：
> 1. **在机器空闲、连续跑 3 次以上**再下结论；单次采样**不可比**；
> 2. 不要把性能采样安排在大构建/安装/测试**之后**；先让它空闲几秒；
> 3. 报告时给出**多次采样的分布**（最小值 ~ 最大值），而不是挑一个数；
> 4. 只有**同一负载状态下**的多次采样才具备可比性。

## 一、启动性能（冷启动，实测打点）

命令：`npm run perf`（构建后真实启动 Electron，由渲染层首帧回报，打印时间线后退出）

| 阶段 | 打点 | 预算 | 实测（2026-09-21 空闲连续 3 次） |
|------|------|------|-------------------|
| 主进程起点 | `main:start` | — | 0ms |
| 窗口创建 | `main:window-created` | < 600ms | ~200–280ms |
| 渲染层首帧 | `renderer:first-paint` | **< 1000ms（可交互）** | **536 / 562 / 632ms** |
| 合计 | — | **< 1500ms（冷启动）** | 同上 ✅ |

> 判定：`npm run perf` 会自行比对预算，超预算则以 **非零退出码**结束（可直接接入 CI）。
> 采集点是真实的（主进程 `Date.now()` + 渲染层挂载后的 `requestAnimationFrame`），不是估算值。
> **引用这些数字时必须连"采样条件"一起引用** —— 单次数字没有意义。

## 三、W7 落地的四件事

1. **启动性能埋点 + 实测**：`main/perfMark` 时间线 + `IPC.PERF_FIRST_PAINT`，
   渲染层挂载后回报首帧；`npm run perf` 打印时间线并做预算判定（可接 CI）。
2. **delta 合批**：流式增量先入缓冲区、用 `requestAnimationFrame` 每帧只刷一次，卸载时清理 rAF。
3. **长会话窗口化**：默认只渲染最近 120 条气泡，更早的按需展开（不引入依赖的过渡方案）。
4. **Tab 懒加载**：连接/对话/外观/终端页改为 `React.lazy` + `Suspense`，失败有骨架屏兜底。

## 四、2026-09-21 首屏依赖瘦身（结果真实，但影响有限）

**动机**：怀疑 `App.tsx` 运行时 import `@jujia/ui-tokens` 把库拉进首屏 chunk。
**改动**：`App.tsx` 改为只做类型导入，外观解析与 CSS 变量注入改为动态 `import()`。

| 指标 | 改前 | 改后 |
|------|------|------|
| 主 chunk | 660KB | **652KB** |
| 主 chunk 内 `bubbleShape` 出现次数 | 6 | **0** |
| ui-tokens | 混在主 chunk 里 | **独立 12KB chunk（懒加载）** |

**如实评价**：改动**确实生效且可验证**，但只占约 8–12KB，
因此**不是**那个"回归"的原因 —— 而那个回归**本身并不存在**（见文首）。

> **2026-09-23 更新**：主 chunk 现为 **666KB**（§二 已更新）。这**不是**本轮改动造成的 ——
> 本轮唯一的渲染层改动是权限页的一行 placeholder 文案（属独立懒加载 chunk，不进首屏）。
> 652KB 是 2026-09-21 的测量值；其后 v0.22–v0.29 的安全加固、钩子/技能/插件与 MCP 接线都进了首屏包，
> 增长属预期，但也说明**拆分这件事一直没做**（见 §五）。
> 口径说明：**体积是确定性产物**（同一次构建可复现），不受文首"采样铁律"约束 —— 铁律只约束时间类指标。
