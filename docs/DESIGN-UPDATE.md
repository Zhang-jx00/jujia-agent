# 自动更新（M12 批二）

> 状态：**无依赖最小形态已交付**（`v0.75.0-铺设15`，R11）。自动下载执行那一档**刻意不开**（见 §三）。

## 一、评估：三条路，选了最小的一条

1. **`electron-updater`（社区主流）**：能自动下载安装包并重启应用 —— 但 (a) 要**新增依赖**（属停牌②），
   (b) 它把"下载二进制 + 执行安装"带进进程生命周期，等于给应用开了一条**自我更新的执行面**，
   与"执行动作都要人点头"的既有纪律正面冲突。
2. **自研自动下载**：把 (1) 的执行面换成自己实现 —— 风险不减、维护面更大。不做。
3. **最小形态（本轮采用）**：**查一次、说一句、指条路** —— 只 GET 一次发布信息，
   显示"有没有新版本"并给出发布页地址；下载与安装交给人（去 GitHub Releases 自己拿）。
   **零新依赖**（用 Electron 自带的 `net.fetch`，系统代理设置生效）。

## 二、形状

- 通道 `APP_UPDATE_CHECK`：**用户点一次、发一次**。没有后台轮询 —— 轮询 = 第二个定时器，
  而且会在没人要求的时候出站。
- 判据是纯规则（`packages/agent-core/src/update/version.ts`）：1–3 段数字 + 可选预发布标记、
  可带 `v` 前缀；**解析不动一律 `null` —— 不猜**；预发布按 semver 口径比正式小
  （`1.0.0-beta < 1.0.0`），预发布内部先后不比（没有真实的消费路径需要它）。
- 服务（`apps/desktop/src/main/update-service.ts`）：8 秒超时（AbortController）；
  四种结局四种话 —— 有新版本 / 已是最新 / **查不到（404：仓库可能尚未公开、或还没有发布过）** /
  查询失败（网络原因或超时，原样带出）。
- 界面（概览页"更新"卡）：当前版本 · 检查更新按钮 · 结果一句话 · 有新版本时给"打开发布页"
  （走既有三档打开方式的系统默认浏览器那一档，**每次硬 ask**，地址即授权）。
- **接线锁**（`main/update-wiring.test.ts`）：三个模块源码**不许出现任何**写文件 / 起进程 /
  下载能力；端点（`api.github.com`）只在一处；更新卡源码里**没有 `useEffect`**（没人点就不出站）。

## 三、刻意不做的（与边界）

- **不做自动下载 / 自动安装**：属**停牌②**（新增依赖 + 新增执行面），要单独定口径才动。
- **仓库尚未公开时**：GitHub API 对私有仓库的匿名请求返回 404 —— 界面如实显示
  "查不到（可能是仓库尚未公开）"，**绝不许显示成"已是最新"**（狼来了与静默失败两头都不能掉）。
  仓库公开之后，同一个按钮即按预期工作。
- **e2e 的注入面**：`JUJIA_UPDATE_API` 环境变量（与 `JUJIA_DATA_BASE_DIR` 同一用法）指向本地假发布页 ——
  **只换"问谁"，不换"问什么"**；e2e 用它把"点了才出站（点前 0 次、点后恰好 1 次）"变成可数的断言。

## 四、隐私口径

这次查询**不带任何本机数据**（一个 GET + 两个固定请求头），也不下载任何东西 ——
它不改变"数据默认不出本机"的边界；这条写在更新卡上给用户看。
