# 画布 ↔ 编码引擎的接驳契约（M9a）

> **轨道接驳计划的交付物**（批复要点④）。这份文档回答一个问题：**画布上的一个节点跑起来时，
> 它到底经过了哪些既有设施** —— 以及哪些是它绝对不许自己做的。
> 上游设计：`docs/DESIGN-M9-CANVAS.md`（九条已批 + 批复追加两条）。

---

## 一、一句话：图只是编排，执行全部复用既有链路

```
画布界面 (CanvasPanel)
   │  ① canvas:save —— 保存前过 validateGraph（成环/重复/缺配置/超限/疑似密钥字段）
   │  ② canvas:run  —— 主进程重新加载 + **二次校验**（磁盘上的图可能被手改过）；
   │                   **带 `fromNodeId` = 局部重跑**（B2：只跑该节点 + 全部下游闭包，
   │                   **同一个 runner 方法**，上游不动；不新增通道）
   ▼
编排层 packages/shared-ipc/src/canvas-run.ts   ← 纯逻辑：拓扑序、状态机、取消、步数上界
   │      它**不碰任何 IO**：执行能力由调用方注入
   ▼
主进程 runner apps/desktop/src/main/canvas-runner.ts   ← 唯一允许"把两者接起来"的地方
   ├── 工具节点   → runTool(…)        → 工具注册表 + **权限门**（读不问 / 写软 ask / 执行硬 ask）
   └── 提示词节点 → streamChat(…)     → 与对话**同一个 provider 流式层**（图自己的 connectionId）
   ▼
事件（带 graphId + nodeId）→ canvas:event → 界面（只认自己那张图的事件）
```

## 二、逐条对照（批复的五条要点 + 追加两条）

| 要求 | 落地 | 证据 |
|------|------|------|
| **① 执行复用既有 Agent Loop 与权限门，不许自建执行器** | 工具节点调 `runTool`（与对话、手动执行**同一个注册表 + 同一个 `permission.resolve`**）；提示词节点调 `streamChat`（与对话同一个 provider 层）。编排层是纯逻辑、不碰 IO | `canvas-runner.ts` 是唯一接线处；接线锁钉住"编排层里不许出现 provider 构造 / `fetch(` / 直接 fs" |
| **② 数据面 + 回退** | 图走 `json-store` 同源（原子写 + 信封 + `.bak` + 损坏隔离）；`id` 只经白名单变路径；空图/超限/带 apiKey 的图**存不进去**；坏文件不进列表但**不删** | `canvas-store.test.ts` 8 例 |
| **③ 有界** | 节点 ≤200 · 边 ≤400 · 单节点配置 ≤8KB · 图 ≤2MB · 单次执行 ≤50 节点；超限一律说话 | `canvas-graph.ts` 的常量与 `validateGraph` |
| **④ 接驳文档** | 本文 | — |
| **⑤ 新资源与新通道都要过"打包后是否仍成立"** | 新依赖 `@xyflow/react`（懒加载成独立 chunk）；新通道五条 + 一条推送；`verify:pack` 目前只覆盖"启动/文件树/PDF"三步，画布**尚未纳入打包验证**（登记待补） | `PERF-BUDGET` 记了 370KB 的懒加载 chunk |
| **追加 (a)：图事件要有归属判别** | 事件在 runner 层补上 `graphId`，过 `canvasEventSchema` 才推；界面**只认自己那张图**（`event.graphId !== graphId` 直接丢） | `canvasEventSchema` 把 graphId/nodeId 设为必填；`CanvasPanel` 的订阅里有这一行 |
| **追加 (b)：图 JSON 不得存 API Key** | 图里只有 `connectionId`；schema 全 `.strict()`（多一个字段就拒）+ **键名扫描**（敏感词元命中且不在豁免清单就拒）；密钥只在 `resolveConnection` 里出现，从不进图 | `canvas-graph.test.ts` 的"带 apiKey 的图存不进去"与豁免清单那两条 |

## 三、节点语义（M9a 的范围）

| 节点 | 配置 | 跑起来是什么 | 与对话的关系 |
|------|------|--------------|--------------|
| **提示词节点** | `{ prompt }` | **单轮补全**（不带工具循环） | 走同一个 provider 流式层与同一条连接；**不产生会话记录**（图有自己的运行记录） |
| **工具节点** | `{ toolName, argsText }` | 一次工具调用 | 与手动执行同一口径：**不**带会话级"总是允许"白名单，每次该问就问 |

**节点状态**：`pending / running / ok / failed / denied / cancelled`。
`denied`（用户拒绝）与 `failed`（执行出错）**是两种状态** —— 前者不是"工具坏了"。

## 四、明确不做（M9a）

控制流节点（条件/循环）· 并行分支 · 局部重跑 · 多图管理界面 · 图执行结果回喂对话 ·
把图当工具暴露给模型（那是另一条链路，要单独设计）。

## 五、已知边界（如实登记）

- **画布未纳入 `verify:pack`**：打包产物验证目前只跑"启动 / 文件树 / 打开 PDF"三步；
  画布的新依赖与新通道属于"打包后可能不同"的范畴，登记为下一步要补的验证项。
- **图事件没有"运行历史"持久化**：跑完只在界面上留最后一次的状态与步骤文本；
  重启后节点状态回到 `pending`（图本身存下来了，跑的记录没存）—— M9b 再谈。

## 六、子代理节点的接线口（**占位契约 —— 未实现**，2026-10-06 裁决归 M14；2026-10-14 细化）

> **状态：未实现、不许宣称。** **子代理节点归 M14**（多子 agent 编排），画布侧只保留**接线口契约占位** ——
> 写得出来是为了将来"接得上"，**不是**为了现在能跑；当前代码里**不存在**这个 kind（现扫只有
> `prompt` / `tool` / `condition` / `loop` 四类）。**硬要求**：README / PROGRESS 等能力表**一律不许**出现
> "支持子代理节点"一类表述（声称与实现不符吃过两次亏）。
> 细化依据：`docs/DESIGN-M14.md`（边界备忘，候选口径已列，拍板前不动工）——细化只加"接口上必须满足什么"，
> **不改任何现有语义、不构成承诺**。

占位契约（将来 M14 做真实节点时的接口约束）：

1. **执行入口**：子代理节点"跑起来"的那一步**必须**落到 M14 提供的执行入口上（与 `agent-loop` 同源），
   **不是**在图里自建第二套循环 —— 与工具 / 提示词节点同一条纪律（§二 要求①）。
2. **每一轮都是真实计费调用**：预算上界（步数 / 时间）在 M14 侧声明为常量并各有测试，形态沿用 B3b 的双上界；
   **到界 = 失败并把"到界"说明白**（不是成功、不是静默截断）。
3. **权限**：子代理内部的一切有副作用动作照旧**逐条**过同一扇权限门（子代理不构成"免审批容器"）；
   子代理**不继承**父会话的会话级「总是允许」白名单 —— "各自独立权限" = **各自独立地过门**，
   不是各自独立的常开开关。
4. **归属**：事件仍须带 `graphId` + `nodeId`（§二 追加要求 a 对任何新节点类型同样成立）；
   子代理内部过程事件若上浮，同样要带归属字段、复用同一套归属判别。
5. **状态与既有语义对齐**：并入同一套 `pending / running / ok / failed / denied / cancelled`；
   `skipped` 不传播、局部重跑（B2）只算该段 —— 既有三套语义（分支 / 重跑 / 循环）对子代理节点**零特判**
   （循环体现为"循环体只有一段提示词"，子代理节点若将来与循环组合，逐轮照常过门）。
6. **取消要进得去**：取消必须传播进子代理（检查点与 B3b 的轮间检查同形），不能只停在图这一层。
7. **汇总产物形态**：节点输出 = **摘要 + 证据引用**；子代理的完整过程留在它自己的记录里，
   不把全文塞进图、也不塞进父上下文。
8. **审计口径**：子代理的工具调用照进同一本执行审计（与对话、画布工具节点同口径：判定与执行都记账）。
9. **打包后仍成立**：若引入新依赖 / 新通道，必须纳入 `verify:pack` 的覆盖范围（§五 既有纪律）。
