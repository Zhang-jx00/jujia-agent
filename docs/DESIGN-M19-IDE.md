# M19 开工报备：轻量 IDE（文件树 + 打开/编辑/保存 + 逐行 diff + PDF 入口）

> **状态：八条全批，第一批（M19a）已交付在 `v0.46.0-M19a`；M19b（CodeMirror 6 + cmap 本地打包）待批。** 依据：复核 T22 后的批复 —— "M19 开工，但要先报备（比 T22 大得多：
> 文件树 + 编辑器 + diff + PDF 入口，属数据面与权限面都变动的范围）。报备要含**范围切分与权限映射**"，
> 外加五条要求（① 保存必须过权限门、只读不问；② 文件读取复用既有路径守卫；③ 有界；
> ④ PDF 用 `pdfjs-dist`、入口在文件树、canvas 渲染、不开 `plugins:true`；⑤ diff 复用 git 读侧）。
> 新变异编号从 **M61** 起。

---

## 〇、这轮的落点是"数据面与权限面"，不是"做个好看的 IDE"

M19 在 `docs/PLAN.md` / `COVERAGE-MATRIX` 里的原话是"文件树 + CodeMirror 6 + diff 视图 + 任务面板"。
但真正会出事的地方不是编辑器长得怎么样，而是：**哪些动作要人点头、由谁守路径、多大的东西能进渲染层**。
所以本轮的验收全落在"真值与边界"上；体验增强（CodeMirror、语法高亮）单独一轮。

## 一、范围切分（批复要求之一）

| | 本轮（M19a） | 下一轮（M19b，另报备） |
|---|---|---|
| 文件树 | ✅ 懒展开 + 单目录条目上限 | 过滤/搜索/Git 状态着色 |
| 打开文件 | ✅ 只读预览 + 分块挂载 + 截断标注 | 语法高亮 |
| 编辑保存 | ✅ 朴素编辑器（整文件写）+ 覆盖保护 + 过权限门 | CodeMirror 6（**新增依赖，单独决策**） |
| diff | ✅ **逐行 patch 视图**（复用 git 读侧，见 §五） | 并排视图 / 逐行暂存 |
| PDF | ✅ `pdfjs-dist` + canvas | 选中取字 / 页内查找 |
| 任务面板 | ❌ 不做（不在批复的五条里） | 待批 |

**为什么把 CodeMirror 拆出去**：它是一组新依赖（`@codemirror/*` ~十余个包）＋一次真实的体积与许可证决策，
而它对"能不能安全地改文件"零贡献。先交付一条**权限与数据都正确**的读写链，再谈编辑器体验 ——
与本仓"先把门做结实，再谈便利"的一贯顺序一致。

## 二、权限映射（批复要求①，逐条对应）

| 动作 | 走哪条通道 | 判档 | 为什么 |
|---|---|---|---|
| 展开目录 | `TOOL_RUN` → `list_dir` | **read → 不问** | 复用既有工具（含路径守卫与截断），**不新写一套**（要求②） |
| 打开/预览文件 | `TOOL_RUN` → `read_file` | **read → 不问** | 同上；256KB 上限与"已截断"标注原样沿用 |
| **保存** | `TOOL_RUN` → `write_file` | **write → 软 ask（每次都要点）** | 要求①：与模型调 `write_file` **同一扇门、同一个弹窗、同一条审计**。界面上不另开"编辑器专用写通道"—— 那等于给写操作开第二扇门 |
| diff / status / log | `GIT_STATUS` / `GIT_DIFF` / `GIT_LOG` | **读侧不问** | 既有口径不变（要求⑤） |
| 打开 PDF | **新只读通道** `PDF_OPEN` | 只读、路径过 `guardPath` | **为什么不走工具层**：PDF 字节是给**人看**的，不是给模型的。走工具层等于给模型新增一个"读任意二进制"的工具（扩大攻击面，收益为零）。所以它在主进程读过路径守卫后**只回渲染层**，不进模型上下文、不产生任何 chat 事件 |

**一句话**：这一轮**不新增任何"判档点"** —— 读走读的口径、写走写的那一扇门；
唯一的例外是 PDF 的字节通道，而它是只读且仍然过守卫。

## 三、有界（批复要求③）

| 对象 | 上限（推荐值） | 超限时的行为 |
|---|---|---|
| 目录条目 | 单目录 500 项 | 如实标注"还有 N 项未显示"，**不静默截断** |
| 文件读取 | 沿用 `read_file` 的 **256KB** | 既有"已截断：共 X 字节，只读了前 Y" |
| 文件保存 | 沿用 `write_file` 的 **2MB** | 既有 `too_large` 拒绝 |
| 渲染挂载 | 沿用文档页的**分块挂载**（一次 240 块） | "已显示前 N / M 段" |
| PDF 文件 | **32MB** | 明确拒绝并说明（"这份 PDF 太大，本机查看不做"），不猜不发 |
| PDF 页数/渲染 | 只渲染**当前可见页**；页数 > 2000 拒绝 | 同上（拒绝要说话，不是卡死） |
| diff patch | 单文件 2000 行 + 总量上限 | 截断并标注（与 `read_file` 同一口径） |

## 四、安全与正确性（不在这五条里，但不说就是隐瞒）

1. **覆盖保护（防静默覆盖）**：打开文件时记下 `size + mtime`；保存前再对一次，不一致就**拒绝保存**并说明
   "文件在你编辑期间被改过"（引导重新打开）。IDE 最经典的事故就是"我编辑器里的旧内容把别人刚写的盖掉了"，
   而 `write_file` 是整文件覆盖语义 —— 没有这一层，工具本身没错、用起来会出事。
2. **审批弹窗的内容预览要有上限**：`PermissionDialog` 现在把参数整体 `JSON.stringify` 进 `<pre>`；
   保存一个 1MB 的文件会让弹窗里塞进 1MB 文本（卡界面，且没有人会读）。建议：**超过 200 行只显示前 200 行**
   ＋"共 M 行（仅预览前 N 行）"。**只动呈现，不动判档**（T19 那轮定的硬 ask/软 ask 口径一个字不改）。
3. **PDF 零出站**（要求④的延伸）：`plugins` 保持 `false`（不执行 PDF 内嵌脚本）；字体/cmap **本地打包**、
   `cMapUrl` 指向本地资源；**不许 pdfjs 去网上取任何东西**。验收用既有的"本地站点台账"手法：
   打开一份 PDF 之后，台账里必须**一个请求都没有**。
4. **PDF 不进模型上下文**：这一轮 PDF 只给人看。"看懂 PDF"是 M11 多模态的事，明确不做。

## 五、逐行 diff 怎么做（批复要求⑤）

- **扩展现有 `GIT_DIFF`**：加 `mode: 'summary' | 'patch'`（默认 `summary`，既有调用与断言不受影响）
  与可选 `path`（只看某个文件）。**不新开通道** —— diff 是 git 读侧的能力，再加一条通道就是
  "同一件事两个入口"，本仓已经反复踩过这个形状。
- 现在 `git.ts` 其实**已经把原始 patch 取回来了**（`raw = rawRes.stdout`），只是当场精简成"关键行摘录"。
  所以这一轮不需要新增 git 能力，只是把"原始 patch"这条路修出去并**加界**。
- 判档：读侧不问，口径不变。

## 六、可测性与验收

- **纯函数层**（新 `ide-guard.ts`，全部可单测 + 变异）：覆盖保护的判定（`shouldRefuseSave(opened, current)`）、
  目录条目截断、patch 截断、PDF 大小/页数拒绝。**判断不留在只有 e2e 碰得到的地方。**
- **e2e（追加 5 步，只能加在"关闭应用"之前）**：
  1. **文件树**：展开一层 → 条目与磁盘 `readdir` 对照（含目录/文件分类）；点开一个文件 → 看到内容
  2. **保存要点头**：改一行 → 保存 → **必然弹软 ask**（写类，与模型调工具同一口径）→ 批准 → **磁盘真值：内容变了**；
     另起一次拒绝 → **磁盘真值：内容没变**
  3. **覆盖保护**：外部把文件改掉 → 编辑器里保存 → **被拒且说明原因**（不做静默覆盖）
  4. **PDF**：打开一份测试里生成的本地最小 PDF → 断言 canvas 真渲染出来、页数正确；
     **本地台账一个请求都没有**（零出站）
  5. **逐行 diff**：改一行 → 打开 diff → 断言那一行以 `+`/`-` 出现（内容真值，不看界面文案）
- 每条新断言做红/绿校准（`TEST-POLICY §六` 第 2 条）；新变异 **M61 起**。

## 七、新增依赖（要单独点一下头）

`pdfjs-dist`（上游标称 **Apache-2.0**，随包分发 → §A；许可证以装完之后 `license:check` 的实扫为准，
不在文档里写死）。当前 registry 实测最新 `6.3.289`（本轮实测查询，不是记忆）。
**只加这一个包**；CodeMirror 那组留到 M19b。

## 八、明确不做

任务面板 · CodeMirror 6 与语法高亮 · PDF 进模型上下文（M11） · 并排 diff 与逐行暂存 ·
文件树里做 Git 状态着色（等 patch 那条路定稿之后再说） · 从编辑器直接执行代码。
