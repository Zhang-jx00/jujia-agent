## 1. 新增范围的定位

| 新增能力 | 一句话 | 为什么值得做 |
|---------|--------|-------------|
| **轻量 IDE 模块** | 不是完整 IDE，只做「看文件 + 改代码 + 看任务」三件事 | Agent 改完代码，用户必须能立刻看到 diff 并微调；否则只能去开 VS Code |
| **接入自己的云主机** | 用户填自己的 SSH/隧道信息，把长任务丢过去跑 | 本机关机就停；长自主任务（数小时）必须能在别处活着 |
| **本地/云端统一调度** | 同一套工具与权限，执行位置可切换 | 微编辑走本地（快），无人值守长任务走云端（稳） |
| **高可定制化外观** | 对话框样式包 + 背景（纯色/图/毛玻璃）一键切换 | 你明确点名的能力，也是"个人"Agent 的核心体验差异 |

### 2.1 五层结构

```
┌───────────────────────────────────────────────────────────────┐
│ ① 客户端层（Electron 桌面）                                    │

└───────────────┬───────────────────────────────────────────────┘
                │ ② 统一会话协议（双向 JSON-RPC 风格，带 seq）
┌───────────────▼───────────────────────────────────────────────┐
│ ③ 会话与调度层（本机 main 进程）                                │

│  权限由本机门控         │       │  权限由**本机**门控（见 §4.4）    │

        │                                   │
┌───────▼───────────────────────────────────▼───────────────────┐
│ ⑤ 状态与产物                                                    │
│  本机：JuJiaData（配置/连接/会话/日志）                          │
│  远端：会话日志 + 产物目录（可回传 diff/截图/日志）               │
└───────────────────────────────────────────────────────────────┘
```

### 2.2 三条不可动摇的设计律

核实到的主流经验（§7 来源）里，有三条直接决定成败：

**律 1 · 会话状态归 host（host-owns-state），不归客户端。**
客户端断开只应是 **UI 事件**，不是状态事件。做法：
- 会话日志（消息、工具调用、权限决策、产物引用）由**正在执行的那一侧**持久化；
- 每条事件带**单调递增序号**；客户端记录 `lastSeenSeq`，重连时**回放增量**，缺口过大则给**新快照**；
- 好处：合上笔记本、切网络、重启客户端都不丢任务。
> 反面案例（已核实）：状态留在客户端或隧道进程里，前者丢整个会话、后者丢当前轮次。

**律 2 · 远端连接一律「出站」，不开入站端口。**
三种传输按优先级：
1. **出站 HTTPS（worker 主动连回本机/中继）** ← 首选，无需改防火墙、无 VPN
2. **SSH（复用用户已有 sshd）** ← 次选，仅依赖 22 端口，无需安装额外组件
3. **反向隧道（dev tunnel 类）** ← 兜底，但**必须账号绑定 + 明确授权**

**律 3 · 绝不允许匿名可达。**
已核实的真实风险：**匿名 dev tunnel 可被未认证访问者触发命令执行**（有厂商文档与安全厂商实测告警）。
因此本项目硬性要求：
- 隧道/worker 必须绑定用户账号或一次性配对码；
- 首次连接必须**用户显式确认指纹**（host key / worker id），并记录到本机信任列表；
- 任何「自动批准远端请求」的开关**默认关闭**，且开启时需要二次确认。

## 4. 本地与云端任务的调度与切换机制

### 4.1 路由决策（确定性规则，不交给模型）

沿用 W5a 的原则：安全与成本相关判定用**确定性规则**。默认规则表（用户可覆盖）：

| 条件 | 目标 | 理由 |
|------|------|------|
| 任务预计 < 2 分钟且只需读文件 | **本地** | 上云反而更慢（环境启动开销） |
| 需要访问本机专属资源（本地服务、本机路径、硬件） | **本地**（强制） | 云上看不到 |
| 预计 > 10 分钟或用户标记「无人值守」 | **云端**（若有可用 host） | 本机关机会中断 |
| 需要重度构建/测试（CPU 密集、长时间） | **云端** | 不占用本机风扇与电量 |
| 涉及敏感凭据 / 未审计的第三方代码 | **本地隔离**（容器，断网） | 降低爆炸半径 |
| 无可用云 host | **本地**，并提示「可接入云主机以支持长任务」 | 不静默降级 |

### 4.2 切换（迁移）机制

任务可**在运行中或暂停时**改换执行位置，要求：

1. **状态可搬运**：会话日志 + 工作区快照（或 git diff）+ 未完成的任务队列；
2. **迁移是显式动作**：UI 上给出「迁到云端继续 / 迁回本地」按钮，并说明将上传/下载什么；
3. **不静默搬运代码**：跨机器传输必须用户确认（尤其含未提交改动）；
4. **失败回滚**：迁移失败时保持原位置继续，且只报告，不清空。

### 4.3 证据回传

远端任务必须能把**证据**带回本机（"证据优先"是既有原则）：
- 文本：stdout/stderr、测试结果、退出码；
- 结构：改动文件的 diff（而非整个仓库）；
- 视觉：截图（用于 UI 类验证）；
- 引用：产物路径 + 内容哈希，便于核对。

### 4.4 权限在哪里判定（关键）

**权限门永远在本机**。远端 worker **不拥有**放行权：
- 远端想调用写/执行类工具 → 事件上抛到本机 → 本机策略层（W5a）判定 → 用户审批 → 结果下发；
- 远端只执行**已被批准的那一次调用**，并把结果回传；
- 好处：换不换执行位置，用户面对的权限语义完全一致；被入侵的远端也无法自助提权。

## 5. IDE 功能与 agent 能力的集成方式

### 5.1 共享一个「工作区抽象」

Agent 与 IDE **操作同一个工作区句柄**，而不是两套文件访问：

```
WorkspaceRef = { kind: 'local', root } | { kind: 'remote', hostId, root }
```

- 工具层的路径沙箱（W3）扩展为对两种 kind 都生效：本地用 `fs`，远端用 worker 的文件接口；
- IDE 的编辑器与 Agent 的文件工具**走同一套读写**，避免「Agent 改了但编辑器没刷新」；
- 文件变更统一走**事件 + 版本号**：编辑器外部改动 → 广播 → Agent 上下文与 UI 同步刷新。

### 5.2 双向联动（这是"集成"的实质）

| 方向 | 行为 |
|------|------|
| Agent → IDE | Agent 改文件 → IDE 自动打开该文件并高亮改动（diff 视图） |
| IDE → Agent | 用户在编辑器里选中一段代码 → 一键「让 Agent 看这段」加入上下文 |
| 任务面板 → 对话 | 面板里点某个工具调用 → 跳到对应对话位置与 diff |
| 对话 → 任务面板 | 长任务在面板里显示进度、可暂停/迁移/取消 |

### 5.3 协议层面

沿用 W3/W4 已有的做法：**所有跨进程/跨机通信都走统一契约 + zod 校验**，
远端新增能力通过同一套 `StreamEvent`/`ToolResult` 表达，不引入第二套协议。
（核实到的 Codex App Server 亦是此思路：用双向 JSON-RPC 暴露 threads/events/diffs/approvals。）

## 6. 高可定制化外观（M23）

### 6.1 三层可定制

| 层 | 可改内容 | 切换机制 |
|----|---------|---------|
| **对话框样式** | 气泡形状/圆角/阴影/边框、头像或标签、时间戳显示、对齐方式、密度（紧凑/舒适） | 样式包（theme pack）一键切换；支持导入导出 JSON |
| **背景** | 纯色 / 渐变 / 图片（本机文件或 URL）/ 毛玻璃（backdrop-blur）/ 透明度 / 平铺方式 | 设置页实时预览，立即生效 |
| **令牌层** | 主色、字体、圆角、间距 | 全部走 `ui-tokens`，改一处全局生效（W6 已规划） |

### 6.2 硬性约束（避免"可定制"变成"不可用"）

- **对比度守护**：用户选的背景与文字若对比度不足，UI **主动提示**并提供一键修复（不静默让人看不清）；
- **不做纯 CSS 注入**：样式包只允许**受控字段**（枚举 + 数值范围 + 受白名单约束的图片路径），
  拒绝任意 CSS/JS —— 否则等于把 XSS 与 RCE 一起请进来；
- **降级**：`prefers-reduced-motion` 下动效关闭；远端图片加载失败时回退到纯色；
- **持久化 + 可撤销**：外观配置进 `config.json`（原子写），提供「恢复默认」。

## 8. 风险与对策（新增部分）

| 风险 | 级别 | 对策 |
|------|------|------|
| 远端被入侵后自助提权 | 高 | 权限门**只在本机**（§4.4）；远端无放行权 |
| 匿名隧道被利用（已核实的真实案例） | 高 | 强制账号绑定/配对码 + 首次指纹确认 + 默认关闭自动批准 |
| 跨机传输泄露代码/密钥 | 高 | 迁移需显式确认；密钥**永不**离开本机、永不进模型上下文 |
| 云上环境与本地不一致导致"在我机器上能跑" | 中 | worker 记录工具链版本并在任务报告里列出；不一致时如实标注 |
| 云主机费用失控 | 中 | 任务显示预计/实际时长；设置预算阈值告警；默认不自动重试长任务 |
| 外观可定制引入 XSS/RCE | 中 | 样式包仅受控字段，拒绝任意 CSS/JS（§6.2） |
| 迁移中途失败 | 中 | 原位置继续，只报告不清空（§4.2） |
