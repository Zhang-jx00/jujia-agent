## 一、为什么单独立项（停牌①）

图片字节随请求发给模型服务商，是**数据第一次主动离开本机** ——
与既有"数据默认不出本机"的表述**正面冲突**。表述要改，只有所有者能拍板，故先报备。

## 二、批复后的新表述（**R14 当年采用的那句；现行定位见 R53**）

> **R14 批复采用的原话（2026-10-13）**：除你主动发起的模型请求（文字 / 图片）外，数据不出本机；附件只发给当前连接的服务商。
>
> **现行定位（R53 · 2026-10-21）**：**默认不出本机；只有你显式接入自己的主机、并显式把任务迁过去时，数据才会去到那台主机。本产品没有服务器。**
> 附件只发给当前连接的服务商这条不变。

落点：README 隐私相关处 + `SECURITY.md` 对应段 + 对话页加图时的一句话（见 §四-⑤）。

## 三、上限与理由（"你来定"的交代）

| 项 | 取值 | 理由 |
|---|---|---|
| 单张大小 | **≤ 5MB** | 覆盖手机截图（1–3MB）与常见照片；再大属于"原图直发烧 token"，批一不做 |
| 每条消息 | **≤ 4 张** | 够"多图对比"的常见用法；上限越多人越不会一次发满，也给 token 与内存一个界 |
| 类型 | **png / jpeg / webp / gif** | OpenAI 兼容协议的常见四类；**以魔数（magic bytes）判定，不信扩展名** |
| 三条都在读盘前判（选择器路径） | | 先 `stat` 再 `readFile` —— 5MB 的界要挡在"把字节读进来"之前 |

## 四、语义（批一范围）

1. **只做"发给模型看"**：对话页可附加图片 → 以 OpenAI 兼容 `content` parts 发给**当前连接**；
   媒体任务 / 视频生成（M11 另一半）**不在本批**（与 M14/M20 的表述冲突问题同批再议）。
2. **附件不落盘（批复 B）**：图片字节**不写**会话 jsonl、不进长期记忆、不进审计正文；
   落盘的只有一行元数据（`imageCount`）。重启后历史气泡显示 **`[图片未保留 ×N]`**（明说，不装还看得见）。
   措辞是"**未保留**"而不是"已过期"：过期暗示"还能再取"，而事实是本机从来没留过副本 —— 一句话要交代的是事实，不是观感。
   发给模型的窗口里，那一轮的 user 消息以 parts 形态携带图片（仅当时、仅内存）。
3. **EXIF 剥离（批复④）**：发出去之前按容器剥掉元数据 ——
   JPEG 丢 `APP1`(EXIF/XMP)/`APP13`(Photoshop)/`COM` 段（**保留 `APP0` JFIF**）；PNG 丢
   `eXIf/tEXt/iTXt/zTXt` 块；WebP 丢 `EXIF/XMP ` 块。**剥不动就不发这张**（fail-closed，并说明原因）。
4. **审计口径**：对话发送（含图）**不在执行审计的记账范围**（那本账记的是"判定与执行"；
   对话发送是用户主动、且从不经 `decideGate`）—— 与"内置终端不进账"同一口径，写进台账备查。
5. **界面把话说明白**：加图后待发清单下方写出实际文案
   "**图片会随本条消息发给「<连接名>」的服务商；本机不保留副本。**"（连接名取当前选中那条）；
   发送本身就是人的动作，**不新增审批弹窗**（不叠加第二道门）。
6. **测试面**：纯规则（魔数/上限/剥离）单测 + 本地回显服务断言 parts；不给"真发出去"留口头承诺。

## 五、刻意不做（批一）

图片落盘与重发 · 多模态历史重放（重发旧图）· 视频/音频 · 图片编辑/缩略图生成 ·
压缩转码（剥 EXIF **不重编码**，画质不动、字节只减不增）。
