## 二、B1 设计

- **对齐辅助线（数学在纯函数里）**：拖动一个节点时，与其它节点做**三线对齐判定** ——
  左/中/右（竖直辅助线）与 上/中/下（水平辅助线）；命中（|差| ≤ 阈值）即显示整条辅助线；
  **吸附 = 取每轴最小差值作为位置修正**。落点：`canvas-bridge.ts` 的纯函数（可单测、可变异），
  渲染层只画线，不做判定。
- **网格与吸附的顺序（写死在一处）**：Grid snap（React Flow 内建 `snapToGrid`）**先**，
  对齐吸附**后**（先落网格、再按对齐差微调）——顺序有单测钉住，不是"碰巧这么写"。
- **命令面板**：`Ctrl+K` 或面板按钮打开；命令集**只封装既有动作**（添加提示词/工具节点、保存、运行、停止、
  适应视图）；执行函数与现有按钮**同一个引用**（接线锁钉"不许新执行路径"）。
- **右键与双击建节点**：`onPaneContextMenu` 弹两个选项（提示词/工具）；双击经 `screenToFlowPosition`
  换算坐标后在落点建节点。
- **等距分布**：B1 **不含**（不在复核给的 B1 清单里；不做"顺手加"）。

## 三、B2 设计：重跑语义（复核点名的唯一设计点）

**入口**：选中一个节点 → 「从此节点重跑」。

**语义（采用第 1–6 条）**：
1. **重跑范围 = 该节点 + 它的全部下游（传递闭包）**：这段子图**整体重置为 `pending`** 再按拓扑序重跑；
   上游已 `ok` 的节点**不动、不重跑**。
2. **旧状态不留"过期"概念**：运行历史本来就不持久化（`LINKAGE-M9.md` §五 已登记），重跑直接把该段子图的
   状态与产出**替换**掉 —— 不留双份状态，就没有"哪份是新的"的歧义。
3. **旧产出不许混进新跑**：被重置节点之间一律用**本次重跑的新输出**；上游（未重置）沿用其最近一次成功输出。
   "拿半成品当输入"的既有底线不变。
4. **复用与停机语义与整图跑完全一致**：同一个 `canvas-runner`、同一把并发锁、同一个停止按钮
   （重跑中按停止 = 当前节点 cancel、其余 cancelled）。
5. **失败即停**：某节点失败/被拒 → 该段停下，未跑的保持 `pending` 并说明原因（与整图跑同口径）。
6. **边界（如实）**：**不支持"只重跑一个节点"**——它的下游会立刻拿到过期输入，正是第 3 条要防的；
   要只跑一段，就用"从此节点重跑"。

**界面显示（复核放行时的追加要求①，已实现）**：用户必须能看出"哪些节点被重跑了"——两条最简形式：
- **节点卡上的「↻ 重跑」小标**：本次重跑段内的节点都带（`data-rerun`，e2e 以此计数）；随**下一次整图运行**或
  **重开图**清掉（运行历史本来就不持久化，"标"是本次会话的记号，不假装是历史）；
- **执行行**：`从 X 重跑：N 个节点（该段已重置重跑；上游未动）`——N 是闭包节点数（不拿回执行数冒充，
  回执行是步骤事件条数、会多一倍）；整图完成的文案同口径改为"N 个节点"。
重跑入口在选中节点的编辑区（「从此节点重跑」，busy 时禁用）；内部走的就是与「运行这张图」**同一个
`canvasRun`**（多带一个起点参数），接线锁钉住"不许第二套执行路径"。

**为什么不选另两个方案**（理由写清，免得反复）：
- *保留下游旧状态、标"过期"*：不持久化运行历史的前提下要发明第二套状态与显示规则，
  而它的价值全建立在"用户会回来查看旧状态"上 —— 与"不持久化"撞车。
- *只重跑选中节点、下游不动*：下游输出变成"新上游 + 旧下游"的混合物，**静默错误**，直接排除。

## 三-B、B3 设计：条件分支（`v0.54.0-M9b-B3`；M9b / M9 收口）

**语义**：条件节点 = `{ prompt, keyword }`。执行 = 一次单轮补全（与提示词节点**同一条** `streamChat` 路径，
执行器**零特判**）；**命中判定在纯编排层**（`canvas-run.ts`）：`回答.includes(keyword)` → 走 `true` 口，
否则 `false` 口。**未选的那支不执行**（连同它的全部下游），状态 `skipped` —— 既不是失败也不是取消
（整体结论照旧可以是 `done`）、**不占步号**、**取消优先于跳过**；汇合点只要有一条活路进来就执行；
局部重跑时**名单外的入边不参与活路判定**（与"上游未动"自洽）。

**两处实现决定（与原设想/旧列的差异，写清免得反复）**：

1. **判定不放进执行器**：原设想让 runner 返回 `branch` 字段；实现时把判定收回纯层 ——
   关键词判定与拓扑序、闭包是同一类纯规则，放编排层后可用注入假执行器全量单测；
   执行器没有"别忘了给 branch"这条失败路径（接线锁钉住："执行器里没有 condition"）。
2. **Handle 补账**：旧列写过"连线"，但此前卡片上**没有 Handle** —— 界面根本拖不出线（e2e 的图
   一直靠"写进盘再打开"验证）。条件节点的"两出口"没有可拖的口就是画着好看，所以本轮一并补上：
   所有节点一个入端；条件节点右侧**真 / 假两个口**（handle id 即 `fromPort`；`canvas-bridge.ts` 收口
   `fromPort ↔ sourceHandle` 互译，认不出的 handle 一律不带口、交给保存前的校验点破）。
   与 B1 补网格吸附同一先例：**文档列过、界面不可达 → 如实补账，不"当没写过"**。

**契约四条**（`canvas-graph.ts`，全部有校验与测试）：条件出边**必须带 `fromPort`**；**每个口最多一条线**；
非条件节点不许带口；`keyword` **非空**（空串的 `includes('')` 恒真 = 静默"总走真口"，直接拒）。

**界面**：卡片关键词行（"含「X」走真口"）；`skipped` 态虚线淡化；连线即时校验加"条件出口已占用"；
执行行有跳过时**分开报数**（"7 个节点：4 个执行、3 个被跳过"）；侧栏 / 右键菜单 / 命令面板三个添加入口。

**边界（如实）**：有界循环**不在 B3**（切给 **B3b 候选**：它要处理"子图重复执行与主拓扑线的关系"，
与 B2 重跑语义有重叠，混进退风险；同当年 M9a→M9b 的切法）；`toPort` 仍未引入（单一入端，
等真的出现多入口节点再加 —— 不加没人用的字段）。
