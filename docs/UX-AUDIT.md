# 体验细节排查表（W6）

> **用途**：把"体验好"拆成可逐项核对的问题清单，避免只凭感觉说"打磨过了"。
> **排查范围**：动画衔接 / 加载性能 / 响应速度 / 交互反馈 / 可访问性 / 稳定性。
> **时间**：2026-09-20（W6）。**状态**：✅ 已修 · 🔶 部分/有取舍 · ⏳ 待后续阶段 · ➖ 不适用
> **配套**：`packages/ui-tokens`（令牌）· `styles/motion.css`（动效与降级）· `features/chat/ToolCard.tsx`

---

## A. 动效衔接（animation continuity）

| # | 问题 | 状态 | 处置 |
|---|------|------|------|
| A1 | 动画时长过长被读成"卡顿"（>300ms 的功能动效） | ✅ | 令牌化：微交互 100ms / 常规 160ms / 面板 240ms；上限 320ms |
| A2 | 缓动曲线用错方向（入场用 ease-in 显得"拖"） | ✅ | 入场 `ease-out`、离场 `ease-in`、屏内移动 `ease-in-out` |
| A3 | 持续型动效（加载指示）误用非线性缓动 | ✅ | 旋转/进度类统一 `linear` |
| A4 | 动画作用于 width/height/top/left 等触发布局的属性 | ✅ | 全部改为 `transform` / `opacity`（见 motion.css 铁律 1） |
| A5 | 工具卡展开做高度动画导致布局抖动 | ✅ | **不做高度动画**：内容做 opacity+translateY 入场，容器高度瞬时变化 |
| A6 | 同屏多个元素同时动画造成视觉混乱 | ✅ | 错峰令牌 `--motion-stagger-step`，且只提供 3 级（限制同时在动的元素数） |
| A7 | 动画缺"收尾"（元素突然消失） | ✅ | 统一用 `both` 填充模式，起止状态都不丢 |
| A8 | 动画与状态变化脱节（点了没反馈） | ✅ | 按钮按压 `scale(0.97)`、工具行状态色随 `running→done` 变化 |
| A9 | 缺少 `prefers-reduced-motion` 降级 | ✅ | 全局降级：时长压到 0.01ms；**位移类动效改为纯淡入**（保留可见结果） |
| A10 | 降级后信息丢失（如展开状态看不出来） | ✅ | 降级只压时长、不改语义：展开的可见结果仍保留 |
| A11 | 毛玻璃在"减少透明度"偏好下仍然生效 | ✅ | `prefers-reduced-transparency` 下 `.jj-glass` 退回不透明背景 |
| A12 | 闪烁频率 >3 次/秒（可诱发癫痫） | ✅ | 全项目无高频闪烁；光标闪烁 1s 周期且受降级控制 |

## 本轮结论

- 新增：**动效令牌体系**、**工具卡 L0–L2**、**四态**、**滚动流畅性优化**、**焦点与键盘可达性**。
- 明确取舍（不做假承诺）：
  - 工具卡展开**不做高度动画**——优先流畅度，牺牲一点"丝滑感"；
  - 虚拟列表、启动性能预算（M18）、读屏复核**留待 W7 与后续阶段**，不在此轮假称完成。
- 已知待办：B3/B4/B5（性能，W7）、E10（读屏人工复核）、A11 的毛玻璃降级需在背景功能落地后回归验证。
