## 〇、缺陷现状（实测读码，不是推测）

- `App.tsx:105` 页签是 App 自己的 `useState`；`:218` 起十个面板全是"懒加载 + 条件渲染"
  （`{tab === 'chat' && <ChatPanel … />}`）—— **切页签 = 卸载**。
- `ChatPanel.tsx` 里 **24 个 `useState` + 4 个 `useRef`** 全是面板自己的：`connectionId` / `sessionId` /
  `pickId` / `bubbles` / `toolLines` / `usage` / `sending` / 三个 hint / 渲染窗口与磁盘分页游标。
  卸载即全丢；重新挂载时 `connectionId` 回到 `''` → 默认选中**第一条连接**。
  （本轮做 6b 的 e2e 时实测撞上：同一句话发到了没密钥的默认连接上，界面报"该连接没有可用的 API Key"。）
- 更重的一半：**流订阅就在面板的 `useEffect` 里**（按会话筛事件的 `sessionIdRef` 那套也在里面）。
  卸载 = 退订。切走之后那一轮的 `text_delta` / `done` / `usage` **没有任何监听者**，
  而那一轮**还没落盘**（落盘发生在轮结束时）→ 切回来看到的是"回答没了"，
  并且下一条消息会**悄悄开一个新会话** —— 旧会话在磁盘上完好，但没有任何地方告诉用户换了线。

## 一、四个方案的取舍（推荐第一个）

| 方案 | 保住"选了哪条" | 保住"正在流的那一轮" | 代价 | 结论 |
|---|---|---|---|---|
| **A. 保持挂载（推荐）** | ✅ | ✅ 订阅一直在，增量照收 | 隐藏期间仍参与 React 重渲染（增量已合批） | **选它** |
| B. 状态提升到 `App` | ✅ | ❌ 退订后事件已经过去了，而那一轮尚未落盘，重读磁盘也读不回来 | 小 | 不选：兑现不了 ③ |
| C. 主进程持有 + 挂载时恢复 | ✅（要新通道） | ❌ 同 B；且"用户上次看到哪"是一个新的持久语义 | 中 | 不选 |
| D. 模块级 store + 重订阅 | ✅ | ❌ 订阅发生在 mount，错过的事件不会重放 | 中 | 不选 |

**③ 是本轮的分水岭**：只有 A 能兑现"接回现有流"；其余三个都得先去解决一个更大的问题（事件不重放）。

## 二、机制：一个 20 行的 `KeepAlive`（语义写清楚，因为它有三条）

- **首次激活前不挂载**（`children` 返 `null`）→ **懒加载性质保住**，首屏 chunk 与启动时间线不受影响
  （与 PERF-BUDGET 里"ui-tokens 不进首屏"是同一个讲究）。
- **激活过一次就一直挂着**；非激活时外层容器带 `hidden`。
  （查过 `styles.css`：`.app-body` 没有给直接子元素写 `display`，所以 `hidden` 的 UA 规则生效；
  若将来有人给它加上 `display`，就以显式 `style.display` 兜底并在接线锁里写明原因。）
- 不引第三方库；不改任何面板的 props（唯一例外见 ③ 那一条：给对话面板加一个 `active`）。

**与 `ErrorBoundary` 的关系（这条不处理就会把修复悄悄抵消）**：`App.tsx:205` 现在是
`<ErrorBoundary key={tab} area={TAB_LABEL[tab]}>` —— 以页签为 key 是**故意**的（换页签即重挂，坏页面自然重来一次）。
常驻的子面板若继续吃这个 key，切页签仍会重挂、状态照样丢。处置：
**对话页单独用一个稳定 key 的边界**，且**错误态下退回旧行为**（面板处于错误态时，切走再切回照旧重挂一次）——
错误态是唯一允许丢弃会话状态的时刻：它本来就没有正常内容可保，而"重来一次"正是用户此刻唯一想要的。

## 三、四个细节（都不是可选项）

1. **滚动位置**：`display:none` 期间元素的 `scrollTop` / `scrollHeight` 读不到，位置实际会丢。
   给 `ChatPanel` 加 `active` 参与：切回时若原本"贴底"就重新贴底一次，用户之前主动上滚过就不抢
   （复用现有的 `stickToBottomRef`，不新增第二套规则）。
2. **隐藏方式用 `hidden` 属性**（语义化、天然 `display:none`、对辅助技术也不可见），不自己写 `visibility`。
3. **只挂"对话"页**：终端页卸载时会 `dispose()` xterm 与 pty、文档页会丢掉已打开的文件与位置 ——
   同类问题确实存在，但**正确解不一样**（终端要谈"pty 常驻"的生命周期）。本轮只做对话页，
   那两处登记待批（见 §五）。
4. **不可见期间的流式渲染成本**：增量合批已经在（`@jujia/shared/stream-batcher`），切回时仍会重渲染。
   本轮**不加**"隐藏就暂停渲染"的优化 —— 那会让"切回来看到的是不是完整内容"取决于优化实现，
   **正确性优先**；要优化也要等 perf 规范采样拿到数据再另开一轮。

## 四、可测性与验收

- **组件测试（jsdom，3 例）**：① 未激活过不渲染子组件（懒加载性质没丢）；② 激活 → 切走 → 再切回，
  子组件本地 state **保留**；③ 非激活时容器带 `hidden`，切回即摘掉。
- **e2e（追加 2 步，只能加在"关闭应用"之前，台账编号不受影响）**：
  1. **选择保持（磁盘真值）**：选回显连接 → 开一个会话问一句 → 记下会话 id 与 `messages.jsonl` 行数 →
     切「文档」→ 切回「对话」→ 断言**连接下拉仍是原来那条**、会话 chip 仍是原来那个 id、之前的问答仍在 →
     再问一句 → 断言回显 `n=2`（同一会话的延续）、`chatList()` **没有多出新会话**、原会话 jsonl 行数 +2。
  2. **流中切走再切回（③ 的字面验证）**：用流式假服务发一问（分 16 段、约 3.5 秒）→ 立刻切「文档」→
     等约 2 秒 → 切回「对话」→ 断言后续增量**继续到达**（等到末段 `A_16_`）且正文完整。
- **红/绿配对**：把 `KeepAlive` 换回"卸载"（等于退回现状）时，上面两条 e2e 断言必须**红**；
  组件测试的 ②③ 同理。三步都留输出（`TEST-POLICY §六` 第 2 条）。

## 五、明确不做 / 登记待批

  **文档页**丢掉已打开的文件与阅读位置。
