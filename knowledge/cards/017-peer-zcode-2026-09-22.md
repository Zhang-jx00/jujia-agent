# 017 · ZCode（zai-org）怎么做的：与 Yan-Agent / openhanako 放在一起看

## 〇、一句话结论

ZCode 是智谱 2026-09-20 开源的 **AI 编程工作台**（Electron 桌面 + 浏览器 Web + 终端 TUI 三形态，统一 `zcode` 命令），
与我们同类但形态更全。它最大的价值不是某个炫功能，而是**把"插件 = skills + commands + mcpServers + userConfig"
打成一个 manifest**、**hooks 覆盖到权限决策本身**、以及**一份写给 coding agent 的 UI 设计法律（DESIGN.md）**。
三者都正好落在我们 W11（技能）/ W5d（钩子）/ ui-tokens 的延长线上。

## 一、产品与仓库事实（2026-09-22 核实）

- 定位原话：**"Z.ai's coding agent harness. Powerful, intelligent, extensible."**；README 称
  "ZCode 是 AI 编程工作台，提供桌面应用、浏览器界面和终端 Agent"。
- 技术栈：TypeScript + Node.js **24.14.0** + pnpm **10.33.2**（**版本以 `mise.toml` 为准**）；
  桌面 Electron；共享 UI 用 React + **Zustand**；Monorepo（pnpm workspace + turbo）。
- 顶层结构：`packages/desktop`（Main/Host/Renderer + 打包）· `packages/web` · `packages/server`（HTTP/WS + 远程连接）·
  `packages/ui`（共享组件）· `packages/services`（业务与持久化）· **`packages/rpc`（RPC 框架）** ·
  `packages/shared` + `packages/client`（协议与 Agent 客户端 SDK）· `packages/provider(-node)` ·
  **`apps/zcode-cli`（Agent CLI/TUI/运行时/工具）** · `.agents/skills` · `harness/remote` · `third-party` · `config`。
- 2026-09-20 "feat: open source" 一次性开源；Apache-2.0；附 `NOTICE.md`（功能/风险声明）与
  `THIRD-PARTY-NOTICES.md`。
- 值得注意的边界声明：**"本仓库随附的 Computer Use 包为不可用占位实现"** —— 开源版与官方产品有功能差，如实标注。

## 二、逐项拆解（与我们逐一对照）

### 2.1 MCP：三种传输 + 每服务器 `timeoutMs` / `enabled`

配置在 `~/.zcode/cli/config.json` 的 `mcp.servers`，支持：

- `stdio`：`command/args/cwd/env/enabled/timeoutMs`
- `http`：`url/headers/enabled/timeoutMs`
- `sse`：同上，且示例里直接演示了 `"enabled": false`

工具命名 **`mcp__<server>__<tool>`** —— 与我们的 `qualifiedName` 方案一致（业界已收敛到同一惯例）。
CLI 内置 `/mcp list|status|connect|disconnect` 会话管理命令。

**对照我们**：我们已做 stdio + 连接同意 + 逐工具批准；差距在 ① 每服务器 `timeoutMs`（今天修的握手超时是全局默认 60s，
ZCode 是 per-server 可配）② `enabled` 开关（我们只有删除）③ http/sse 传输（我们只有 stdio）④ `/mcp` 会话命令。
→ **采纳：per-server `timeoutMs` 与 `enabled` 进 W10 后续或 W11 配套**（改动小、直接补今天暴露的痛点）。

### 2.2 Hooks：七类事件，且 **PermissionRequest 是一类 hook**

事件全集：`SessionStart` / `UserPromptSubmit` / `PreToolUse` / **`PermissionRequest`** / `PostToolUse` /
**`PostToolUseFailure`** / `Stop`。关键契约（每一条都值得抄）：

- **默认禁用**（`hooks.enabled: false`）—— 钩子是"给懂的人的自动化"，默认关。
- **argv 执行而非 shell 字符串**（"using argv execution rather than a shell string"）—— 与我们
  `buildServerCommand` 的原则一致。
- **stdin 收一个 JSON、stdout 回一个 JSON**；空 stdout = no-op；非 JSON / schema 非法 / 超时 / 非零退出
  → 记为 hook 失败但**不崩 turn**；**exit code 2 = 显式 block/deny**。
- `PreToolUse` 可 deny / **ask** / allow / **改写工具输入** / 补充上下文；
  **`PermissionRequest` 可 allow / deny / 改权限 / 改待批输入** —— 这一条与我们的权限门天然咬合：
  用户可以写一个"我的审批策略程序"参与决策，而不是只有 UI 弹窗一条路。
- `Stop` 可 `continue: true` 要求再走一步（有循环上限，防死循环）。
- 全局 `hooks.timeoutMs`（默认 60s）+ `maxOutputBytes`（32KB 上限）+ per-hook 覆盖。
- `matcher` 是 JS 正则字符串，按组顺序执行。

**对照我们**：W5d 计划四类（Pre/PostToolUse、Stop、SessionStart）。→ **采纳：W5d 按 ZCode 的七类 + 上述契约设计**，
尤其 PermissionRequest 类（接进 `decideGate` 之后成为"规则表之外的程序化规则"）与 exit 2 = deny 的语义。
我们的 `mutations.json`/权限门测试基建正好能锁这些行为。

### 2.3 插件系统：一个 manifest 打包 skills + commands + mcpServers + userConfig

`plugin.json` 字段：`name/version/description/author/license`、`skills`（SKILL.md 目录）、
`commands`（markdown 自定义命令）、`mcpServers`（内联或路径）、`userConfig`（`${user_config.key}` 展开的选项默认值）。

安全与工程细节（全部值得抄）：

- **变量展开只认 `ZCODE_` 前缀**的环境变量（`${ZCODE_PLUGIN_ROOT}` / `${ZCODE_PLUGIN_DATA}` /
  `${ZCODE_PROJECT_DIR}` / `${user_config.key}`）；**缺失变量 → 禁用该 MCP server 并产生诊断**（fail-closed 且可见）。
- **插件数据与代码分离**：`cache/` 放代码，`data/<plugin-id>/` 放运行时输出 ——
  "MCP servers should write runtime output here, not into the plugin source directory"。
- **官方市场 = 内置 + CDN（sha256 校验的 zip）**；个人来源（git/GitHub/URL/本地目录）单独分段展示。
- **高风险/重运行时的官方插件默认禁用**，用户显式 enable 才装（`ios-simulator`、`android-emulator` 等）。
- 卸载内置插件进入"持久化抑制态"，重启**不**自动重新播种（Restorable Builtin）—— 尊重用户决定。
- 边界原则原话：**"keep all process/file/network side effects inside the MCP server boundary"**。

**对照我们**：W11（Skills + 定时任务）还没开始。→ **采纳：W11 的技能/插件模型按"一个 manifest 打包
skills+commands+mcpServers+userConfig"设计**；变量展开**只认 `JUJIA_` 前缀 + 缺失即禁用并诊断**；
高风险内置技能默认禁用。这与我们"默认不放行"的骨架完全同构，不冲突。

### 2.4 权限模式与诚实声明（NOTICE.md 值得逐句学）

- 权限模式命名：共享配置默认 **`build`**；CLI 非交互 `--prompt` 未指定 `--mode` 用 **`yolo`** ——
  且明确警告"未同时启用只读规划约束的 yolo 会放行普通工具操作"。
  （对照我们：default/acceptEdits/plan/dontAsk/bypassPermissions —— 语义相近，我们的命名更直白。）
- 风险声明的好句子（我们 SECURITY.md 应吸收的句式）：
  - **"模型声称'已完成''已安全处理'或'已获授权'不构成事实或授权证明。"**
  - **"停止会话、切换页面或取消某次请求，不能撤销已经完成的文件写入、发布、上传或其他外部操作。"**
  - "不能保证每份外发内容都由用户逐项选择或每次外发都有独立确认。"
  - 凭据"采用本地加密文件……**并非系统钥匙串**……不应视为'始终不离开本机'的保证"
    → **我们的 SECURITY.md 也应这样如实写**（我们的密钥是本地加密文件 + 环境派生密钥，同样不是系统钥匙串）。
  - 打包版**忽略**更新源覆盖环境变量（开发入口不泄漏到生产）。
- 权限边界诚实化："模型工具审批不是整个应用的统一权限开关" —— 审批只覆盖它覆盖的地方，别夸大。

### 2.5 给 coding agent 的文档实践（DESIGN.md / CONTEXT.md）

- **DESIGN.md = UI 设计法律**：强制 `text-ui-*` 字阶（禁止任意 `text-[13px]`）、语义色 token（禁止 raw 值）、
  圆角嵌套层级、覆盖层层级；**"违反此节被视为 design-system defects 而非风格偏好"**。
  —— 与我们 `ui-tokens` + W23 样式包同路，但他们把规范**写成给 agent 的硬约束文档**。
  → **采纳：把我们 ui-tokens 的用法约束写成 `docs/DESIGN.md`**（哪些类必须用 token、哪些是缺陷），
  供我自己和外部贡献者的 agent 共同遵守。
- **CONTEXT.md = 按功能的领域词汇表**：每个术语 = 定义 + **_Avoid_（禁用的叫法）**。
  例如区分 Official Marketplace / Builtin / CDN Plugin、Store Listing vs Plugin Manifest、
  Restorable Builtin / Orphaned Installed Plugin。统一语言能防文档、UI、代码三处各说各话。
  → **采纳：W11 动工前先写技能/插件的 CONTEXT 词汇表**（"技能 vs 插件 vs 命令 vs MCP 服务器"的精确定义）。

### 2.6 工程与发布

- **CLI 运行时零生产依赖**（用 Node 内置做参数解析与终端控制）；正常 bundle 为主，SEA 单文件为可选路径，
  下载 Node 二进制**对照 SHASUMS256 校验**；"native addons 与动态 import 在 SEA 兼容性证明前不进核心 CLI"。
- **发布通道**：`releases/<version>/tar.gz + sha256.txt + latest.json + install.sh`；安装脚本从下载根拉取。
- **第三方声明生成 + 发行前校验，校验失败阻断发布**（`third-party/README.md`）。
- **mise.toml 锁工具链版本**（Node + pnpm），README 开头就写"版本以 mise.toml 为准"。
- 子代理/后台任务的不可撤销性、附件"发送前预传输"、会话分享是公开投影 —— 风险声明覆盖到了我们没想到的角落。

**对照我们**：→ **采纳（低成本高价值）**：① Release 产物补 `SHA256SUMS`；② `package.json` engines +
`.nvmrc`/`mise.toml` 锁 Node 版本；③ SECURITY.md 吸收 2.4 的诚实句式。

## 三、三项目横向对比（共性 = 业界惯例，差异 = 选型）

| 维度 | ZCode（智谱） | Yan-Agent | openhanako | 我们（俱佳Agent） |
|------|--------------|-----------|------------|------------------|
| 形态 | 桌面+Web+TUI 三合一 | 桌面 | 桌面（Hono 独立服务进程） | 桌面（单机，本地优先） |
| MCP | stdio/http/sse，per-server timeoutMs/enabled，`mcp__srv__tool` | 有 MCP 支持 | 有（better-sqlite3 持久化会话） | stdio ✓（http/sse 未做），**同名命名惯例**，同意流更重 |
| 工具命名 | `mcp__<server>__<tool>` | — | — | **相同**（qualifiedName） |
| Hooks | 7 类含 PermissionRequest，exit 2=deny，默认禁用 | — | — | 计划 4 类（W5d）→ **升格为 7 类** |
| 技能/插件 | plugin.json 打包 skills+commands+mcpServers+userConfig | `lib/skills/<name>/SKILL.md` + builtin.json | skills2set 目录 | W11 未开始 |
| 权限 | build/yolo 等模式 + 工具审批 + hooks 参与决策 | — | — | 5 模式 + 规则表 + **逐工具同意（更细）** |
| 会话状态 | 会话归 host（RPC + server 包），Web/桌面共享 | 单机 | Hono 独立服务 + sqlite | 单机 + IPC；**RPC/多形态未做（对应 M20–22）** |
| 发布 | tar.gz+sha256+latest.json+install.sh；SEA 可选 | Release 附件 | Release | Release exe（**缺 SHA256SUMS**） |
| 文档 | README+DESIGN+CONTEXT+NOTICE+third-party | README 徽章+双语 | README | README+SECURITY+CONTRIBUTING（**缺给 agent 的设计法律/词汇表**） |

**三家共性（可直接当成惯例）**：MCP 工具名 `mcp__<server>__<tool>`；技能 = `SKILL.md` 目录约定；
skills/commands/MCP 可同源打包；发布带校验和；第三方声明独立成文档；Node 版本锁死并写进文档。

**ZCode 独有、我们最该学的**：PermissionRequest hook（权限决策可编程）· 变量展开只认自家前缀 + 缺失即禁用 ·
DESIGN.md 作为给 agent 的硬约束 · CONTEXT.md 领域词汇表 · 不可撤销副作用的诚实声明。

## 四、借鉴清单（按可落地性排序，含落点）

| 优先级 | 借鉴什么 | 落点 | 与现有结构的关系 |
|--------|----------|------|------------------|
| 高 | W5d 钩子按 ZCode 七类事件设计，契约照抄（argv/stdin-JSON/stdout-JSON/exit2=deny/maxOutputBytes/默认禁用） | W5d | 直接落在现有权限门 + `decideGate` 旁，PermissionRequest 类接进 gate |
| 高 | per-server `timeoutMs` 与 `enabled` 开关 | MCP 设置页 + mcp-store | 今天修的 60s 全局默认之上加细粒度；改动小 |
| 高 | SECURITY.md 吸收 NOTICE 的诚实句式（不可撤销副作用 / 非系统钥匙串 / 外发不保证逐项确认） | SECURITY.md | 纯文档，立即做 |
| 高 | Release 产物补 SHA256SUMS；engines + .nvmrc 锁 Node | 发布流程 | 我们已有 Release 脚本，加一步生成校验和 |
| 中 | W11 技能/插件模型 = 一个 manifest 打包 skills+commands+mcpServers+userConfig；变量只认 `JUJIA_` 前缀、缺失即禁用并诊断；高风险内置默认禁用 | W11 设计前置 | 与"默认不放行"同构；先写 CONTEXT 词汇表再动工 |
| 中 | `docs/DESIGN.md`：给 agent 的 UI 硬约束（必须用 ui-tokens 语义类、违反视为缺陷） | docs | ui-tokens 已有，补"法律文本" |
| 中 | `/mcp` 类会话命令（列表/状态/连接/断开） | MCP 页或对话斜杠命令 | 我们已有 UI 面板，可后置 |
| 低 | http/sse 传输 | agent-core/mcp | stdio 已稳，远程 MCP 出现需求再做 |
| 低 | 数据目录环境变量（对齐 ZCODE_DATA_BASE_DIR） | 已有等价物（数据根固定），可选 | — |

**明确不抄**：`yolo` 作为非交互默认（与我们"默认不放行"相悖，我们的 plan/dontAsk 更稳）；
共享运行配置（我们坚持本地单机）；Computer Use 占位包；多形态 RPC（M20–22 再说）。

## 五、本轮已立即落地的

- **握手独立超时 `initializeTimeoutMs`（默认 60s）+ 超时提示语**：直接回应今天实测的 55.2s 首连超时；
  与 ZCode 的 per-server `timeoutMs` 思路同向（它是 per-server 可配，我们先做全局默认，细粒度进借鉴清单）。
  提交：`v0.14.4-mcpfix`。
