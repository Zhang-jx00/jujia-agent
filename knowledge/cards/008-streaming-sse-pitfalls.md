# 008 · SSE 流式对话：边界、尾包与「中止不是异常」

## 落地决定

1. **必须把「SSE 解析」抽成纯函数并单独重测**（`packages/agent-core/src/providers/sse.ts`）。
   网络分块与事件边界**毫无关系**：一个事件可能横跨多个 chunk，一个 chunk 也可能含多个事件。
   实测中「一个字符一个字符地写」的极端分片也能正确拼装。

2. **`flush()` 必须处理「末尾没有换行符的最后一行」。**
   实测缺陷：初版只在遇到 `\n` 时才解析行，服务端**直接断流**（没有结尾空行）时最后一个事件会丢。
   现象是「回复少了最后一段」，且只在某些服务端/代理下出现——典型的静默丢数据。
   修复后 `sse.test.ts` 与 mock 服务端的「无 `[DONE]` 直接断流」用例同时把它锁死。

3. **用户中止（AbortSignal）是正常路径，不是异常。**
   契约：正常结束与中止都产出且仅产出一次 `done`（reason = `stop|length|aborted`），
   只有 HTTP/网络/结构错误才抛 `ProviderError`。否则 UI 会把「我按了停止」显示成报错。

4. **错误分三类，语义不能混**：
   - `http_error`（带 status，如 401/403/429）→ 提示用户检查密钥/额度
   - `bad_response`（200 但结构不是 SSE / data 里带 error / 全是无法解析的负载）→ 上游实现异常
   - `network_error`（连不上、流中断）→ 网络问题
   特别地：**全是垃圾负载时必须报错，不能静默成功**（否则用户看到空白回复却没有任何提示）。

5. **验证方式：用 `node:http` 起真实本地 SSE 服务，而不是打桩 fetch。**
   `openai-compat.test.ts` 里 14 个用例覆盖：多段增量顺序、逐字符慢写、usage 与 finish_reason、
   无 `[DONE]` 断流、401、data 内 error、全垃圾负载、中止、连不上、请求体字段与鉴权头。
   这套测试不需要任何真实 API Key，CI 上也能跑。

## 边界与后续

- W2 只实现 **openai-compatible** 一档；Anthropic 档（messages API / 不同 SSE 事件名）在 W3+ 补，
  届时复用同一套 `ProviderEvent` 契约与测试骨架。
- 会话历史目前只在内存（`Map<sessionId>`），落盘 jsonl 与压缩属 W3（记忆模块）职责。
- 错误的轮次**不写入会话历史**（避免把报错文本当上下文喂回模型）。
