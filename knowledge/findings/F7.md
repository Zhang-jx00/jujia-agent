## Summary

为 Windows Electron 桌面 Agent 建立可落地的 UI 知识基线：采用 **三/四层 Design Tokens**（ref → system → component → agent-specific）驱动主题；桌面优先对齐 **Fluent 2 / Fluent UI React v9**（Card、MessageBar、Toast、Skeleton、Dialog、Badge 等已覆盖 Agent 卡片与状态反馈）；聊天与工具调用界面参考 **Open WebUI（Live Workflow/Message Flow）与 LobeHub（Agents as unit of work + DESIGN.md token 体系）**；信息架构核心是 **渐进披露**（默认摘要卡 → 展开参数/日志/推理）与 **权限审批/差异审查面板**；空/载入/错误状态严格按 **NN/g 三指南**；动效采用 **M3 时长/缓动 token** 并尊重 `prefers-reduced-motion`；可访问性关键点是 MessageBar 的 `aria-live` 分级与焦点陷阱。

### 1. Design Systems 与 Design Tokens（桌面 Agent 选型）

**结论**：桌面 Agent 不要硬编码颜色/字号/阴影；用语义 token 名（如 `colorBgContainer`、`md.sys.color.primary`）消费，禁止写 hex。

- **Material 3 三层 token 架构**（可直接映射 Electron CSS variables）：
  1. **Reference** `md.ref.*` — 原始色板/数值（如 `md.ref.palette.primary40 = #6750A4`）
  2. **System** `md.sys.*` — 语义角色（`md.sys.color.primary`、`md.sys.color.on-surface`、`md.sys.typescale.label-large`）
  3. **Component** `md.comp.*` — 组件槽位（`md.comp.filled-button.container.color` → system → ref）
- **LobeHub lobe-ui 模式**（`DESIGN.md`）：
  - 主题经 `ThemeProvider` + CSS variables（cssVar key `lobe-vars`）运行时切换 light/dark
  - 用户可配置 primary/neutral（默认 primary 近黑/近白，保持界面冷静；选色后才带 hue）
  - 语义色：`colorPrimary/Success/Warning/Error/Info` + 派生坡 `color{Name}Hover/Active/Bg/Border/Text/Fill*`
  - 表面层独立：`colorBgLayout / Container / ContainerSecondary / Elevated / Spotlight`
  - 文字坡：`colorText → Secondary → Tertiary → Quaternary`（信息分层用透明度阶，不靠颜色）
  - 边框/填充用半透明 `rgba`，可叠在任意背景上
- **Fluent 2**：Web 用 `@fluentui/react-components` + `FluentProvider theme={webLightTheme}`；Web Components 用 `@fluentui/tokens` + `setTheme(webLightTheme)`。

**Electron 落地**：

### 3. Card 信息架构（Fluent Card 用于工具调用卡）

Fluent Card 官方 anatomy 与行为可直接作为 **ToolCallCard** 骨架：

- **槽位**：`CardHeader`（工具名 + 状态图标 + 时间）/ `CardPreview`（输出摘要、diff 预览、图片）/ `CardFooter`（允许/拒绝/重试/复制路径）
- **对齐**：垂直（header → body → footer）或水平（紧凑时间线列表）
- **尺寸行为**：auto height + fixed/block width；消息流内卡片宜 `fit-content` 高度、流宽
- **交互模式**：
  - 多操作 → header/footer 放按钮
  - 单一明显操作 → 整卡可点
  - 可选中（多工具批量审批）→ `floatingAction` 增强选中暗示
- **焦点**：`focusMode`：
  - `off` — 仅卡内 action 可聚焦
  - `no-tab` — 卡可聚焦并 trap，Tab 在 action 间循环，ESC 退出
  - `tab-exit` — Tab/ESC 均退出
  - `tab-only` — 卡可聚焦但不 trap
- **内容原则**：卡片只放「先要知道的」 bite-sized 信息 + 可行动作；细节进展开/Drawer。

**ToolCallCard 推荐信息层级（Electron）**：

```
┌──────────────────────────────────────────┐
│ [icon] ToolName          [Badge: running]│  Header
│ command / path · 2.3s                    │  meta
├──────────────────────────────────────────┤
│ "Wrote 3 files in src/renderer/ui"       │  1-line summary
│  + tokens: 1.2k · model: xxx             │  meta chips
│  [Skel →] stdout snippet (2 lines)       │  Preview
├──────────────────────────────────────────┤
│ [View details] [Copy] [Retry]            │  Footer
└──────────────────────────────────────────┘
  点击「View details」→ Drawer：完整 args/json、stdout/stderr、diff
```

**Sources**: [Fluent Card usage](https://fluent2.microsoft.design/components/web/react/core/card/usage)

### 4. 聊天 / 消息 UI 模式

综合 Open WebUI、LobeHub 与 Conversational UI 指南：

| 模式 | 做法 | Electron 细节 |
|------|------|---------------|
| 消息流 | 用户/助手/系统三种气泡；工具调用是流内卡片，不是终端噪音 | 虚拟列表（react-virtuoso）避免长会话卡顿 |
| 流式渲染 | 边收边渲染；`reasoning_content` 与正文分离 | 主进程 IPC 分片推送；渲染层 diff 更新，勿整段重挂 |
| 排队消息 | Open WebUI：AI 响应中可排队，就绪后自动发送 | Composer 提交时若 busy → 本地队列 + 状态提示 |
| Markdown/LaTeX | 完整 MD + 代码高亮 + 数学 | markdown-it / streamdown；代码块独立 CodeBlock 卡 |
| 活工作流 | Open WebUI **Live Workflow & Message Flow**：实时 checklist 构建 | Agent 任务用 checklist 时间线卡，步骤状态实时更新 |
| 多模型并行 | Open WebUI Multi-Model Conversations | 可后置；MVP 单模型 |
| Notes/Artifact | Open WebUI Notes、Persistent Artifact Storage | 右侧 Drawer 存工具产物/文件预览 |
| 空会话 | 见 Topic 6 空状态 | 提供 starter prompts + 技能入口 |

**Composer 建议**：底部固定输入条；Enter 发送 / Shift+Enter 换行；附发送中/停止；附件与技能 chips 在输入区上方；Windows 密度下高度建议 ≥ 88px 含操作栏。

**Sources**: [Open WebUI GitHub](https://github.com/open-webui/open-webui) · [LobeHub README](https://github.com/lobehub/lobehub) · AI UX Conversational UI guide (search corroboration)

### 5. 工具调用卡 IA 与权限审批 UI

#### 5.1 工具调用卡（Tool-call Card IA）

推荐三层披露（对应 Topic 7）：

| 层级 | 内容 | UI |
|------|------|-----|
| L0 折叠摘要 | 工具名 + 状态点 + 一行意图/结果 | 时间线中 40–56px 高的一行 |
| L1 展开卡 | CardHeader/Preview/Footer：关键参数、结果摘要、计数 | 同流内展开（Accordion） |
| L2 详情面板 | 完整 JSON args、stdout/stderr、文件 diff、耗时/token | Drawer 或 Dialog |

状态语义（与 Badge/状态点共用 token）：

| 状态 | 颜色 token | 图标语义 |
|------|------------|----------|
| queued | textTertiary | clock |
| running | info / primary + 轻微动效 | spinner / pulse |
| waiting-approval | warning | shield / hand |
| success | success | check |
| error | error | alert + 可 Retry |
| cancelled | textSecondary | stop |

#### 5.2 权限审批 UI（Permission Approval）

从 Open WebUI「Tools/Filters/Actions + approval flows」、LobeHub「user owns judgment」与 HITL 模式归纳：

**卡片结构**：

```
┌──────────────────────────────────────────┐
│ ⚠ Permission required      [warning]     │
│ Run command / Write file / Network call  │
├──────────────────────────────────────────┤
│ Agent wants to:                          │
│   exec: npm test                         │
│   cwd: D:\MiMo\ProjectOne\...            │
│ Scope: this session / this tool / once   │
├──────────────────────────────────────────┤
│ [Allow once] [Allow for session] [Deny]  │
│ [Edit args]  [View details]              │
└──────────────────────────────────────────┘
```

**交互规则**：
1. **默认阻塞流**：等待审批时 Agent 状态 = `waiting-approval`，Composer 可继续输入但提交会插入队列
2. **按钮文案**：动词+名词，禁止单独的「确定/OK」（LobeHub Voice 规范）：`Allow once`、`Deny`、`Allow all tools this session`
3. **危险操作**：使用 Dialog（Fluent）而非 toast；错误/警告不可被静默 dismiss 后消失（Fluent MessageBar 规则：警告/错误若未采取行动，下次会话会重现）
4. **升级路径**：多次同类工具请求 → 提供「Always allow for this tool」复选，但写操作/网络/删文件默认永远询问
5. **焦点**：审批 Dialog 打开时焦点进入首要安全按钮（通常 Deny 旁或 Allow once）；支持键盘 `A`/`D` 快捷（需设置页开关）
6. **可读性**：完整命令/路径可复制；长参数截断 + 展开
7. **透明**：说明「为什么 Agent 要做这个」（来自 plan/工具描述），不只给命令

**Electron**：主进程 `permission:request` → 渲染层队列组件；系统级通知（Tray/Notification）在窗口失焦时提醒；拒绝写入审计日志（本地 jsonl）。

**Sources**: [Open WebUI features](https://github.com/open-webui/open-webui) · [LobeHub DESIGN.md Voice](https://github.com/lobehub/lobehub/blob/canary/DESIGN.md) · [Agentic Design — HITL / Approval Queues](https://agentic-design.ai/patterns/ui-ux-patterns/progressive-disclosure-patterns)

### 6. 空状态 / 加载 / 错误状态（NN/g + LobeHub）

**NN/g《Designing Empty States in Complex Applications》三指南**：

1. **传达系统状态**  
   - 禁止「空白面板」；完成后必须有系统消息（如「所选日期范围内没有记录」）  
   - **禁止误导性空态**：加载中绝不能显示 “No records”，否则用户会立刻离开且失去信任  
   - 处理中用 **progress indicator**，完成后才切空态消息

2. **提供学习线索（pull revelations）**  
   - 空态顺带教功能：「收藏后会显示在这里」  
   - 上下文帮助优于强制教程（对 Agent：空会话解释如何下第一单/如何开技能）

3. **提供关键任务直达路径**  
   - 空态内放 **Create / 开始按钮** 与 **Learn more**  
   - Agent 示例：空会话 →「新建任务」「打开示例会话」「配置 Provider」；空记忆 →「从对话提取记忆」

**四态矩阵（LobeHub Do）**：每个表面都设计 empty / loading / error / success，禁止只做 happy path。

| 状态 | 组件 | 文案模式 |
|------|------|----------|
| Empty | EmptyState（图标+标题+说明+CTA） | 说明「将会显示什么」+ 一个主 CTA |
| Loading | Skeleton（内容形）> Spinner（短）> Progress（可测进度） | 禁止假装 empty |
| Error | MessageBar(error) 或 ErrorState | 事实 + 可行动按钮（Retry / View logs / Switch model） |
| Success | 静态内容 / MessageBar(success) 临时 | 命名具体变化，避免 “successfully” |

**Agent 特有加载**：LobeHub 建议 AI/loading 用系统专用 loader（skeletons、`NeuralNetworkLoading`）而非 ad-hoc spinner。Electron 可自研「思考中」三点/神经元动效，但须可 reduced-motion。

**Sources**: [NN/g Empty States](https://www.nngroup.com/articles/empty-state-interface-design/) · [LobeHub DESIGN.md](https://github.com/lobehub/lobehub/blob/canary/DESIGN.md)

### 7. 渐进披露（Progressive Disclosure）

**NN/g（Jakob Nielsen）**：
- 初始屏只放最重要少数选项；高级项按需二级展示
- 收益：learnability、效率、更低错误率
- 两个必须做对的点：**(1) 初级/次级切分正确**（高频前置）；**(2) 推进路径明显**（机制简单 + 标签有 information scent）
- 通常 **不要超过 2 层**；3+ 层易迷路
- 与 **staged disclosure**（向导分步）区分：渐进是「核心 vs 次要」层级导航；staged 是「任务先后」线性步骤

**AI/Agent 落地（Agentic Design + aiuxdesign）**：

| 信息 | 默认 | 展开 |
|------|------|------|
| Agent 推理 | 结论/下一步 | reasoning steps → full trace |
| 工具调用 | 一行摘要 | 卡片 L1 → Drawer L2 |
| 错误 | 发生了什么 + 修复按钮 | why + technical details |
| 设置 | 常用（模型、权限模式） | 高级（温度、上下文窗口、自定义 system） |

**Do / Don't**（可写进 agent UI 规范）：
- ✅ 只默认展示必要信息；统一 expand/collapse 图标；展开有短动效；记住用户披露偏好；提供 Expand all / Collapse all
- ❌ 一次倾倒全部复杂信息；误导标签；嵌套 >3 层；关键信息藏多层点击；忽略键盘导航
- ⚠ 陷阱：「隐藏必要项以显得简洁」— Clean ≠ usable；若用户反复展开同一内容，应提升到默认层
- ⚠ 门要明显：标签化触发器（「Show 4 more」）优于神秘 chevron
- ⚠ 深度上限约 2 层；第三层说明 IA 有问题
- ⚠ 在「需要的时刻、需要的旁边」披露，而不是遥远的设置页

**Electron 实现**：`Disclosure` 原语（aria-expanded、按钮可键盘操作）；工具卡默认 collapsed；设置页 Primary/Advanced 分组；localStorage 记住 `expandedTools` 偏好。

**Sources**: [NN/g Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) · [Agentic Design PDP](https://agentic-design.ai/patterns/ui-ux-patterns/progressive-disclosure-patterns) · [aiuxdesign Progressive Disclosure](https://www.aiuxdesign.guide/patterns/progressive-disclosure)

### 8. 反馈体系：MessageBar vs Toast vs Dialog

**Fluent MessageBar 官方分工**：
- **MessageBar**：关于「当前表面/页面/抽屉/对话」状态的重要信息
- **Dialog**：要阻止破坏性操作时
- **Toast**：时效性、且与「别处」活动/状态相关

**MessageBar 类型与规则**：

| 类型 | 何时 | CTA |
|------|------|-----|
| Info | 有帮助、非必须立即行动 | 可选 |
| Success | 与该表面相关的成功 | 可选；不写 “success”，写具体变化 |
| Warning | 临时/可能有害状态 | **必须**有 button/link |
| Error | 阻断继续的问题 | **必须**有 button/link |

**行为**：
- 内容不截断；约第二行后 action 换行到正文下方
- 可 dismiss；但 **warning/error 若未解决，下次会话重现**
- 多条堆叠顺序：**Error → Warning → Success → Info**
- 多条可收成 accordion：最高严重级别作标题 + 数量 badge
- 位置：page（命令栏下）/ container / tab / card / form / drawer
- Form 错误：焦点移到顶部 MessageBar，字段级 inline error 同步强化
- 文案：Title 可选但利于扫描（「Almost out of storage」优于「Warning」）；Body 1–2 句；Sentence case；按钮直接回应标题（`Renew license`）

**Toast（Electron）**：
- 成功工具完成、后台 cron 完成、下载完成 → Toast
- 可撤销操作的 Toast 必须带 `Undo`
- 托盘/系统 Notification 用于窗口失焦时的审批请求

**Sources**: [Fluent MessageBar](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage) · [Fluent Components](https://fluent2.microsoft.design/components/web/react)

### 9. 可访问性（A11y）

| 领域 | 规范 | Agent UI 应用 |
|------|------|----------------|
| Live regions | Error/Warning MessageBar → `aria-live="assertive"`；Info/Success → `polite` | 工具失败用 assertive；成功用 polite；勿满屏 assertive |
| 焦点 | 可见 `:focus-visible` 环；Dialog/审批 trap focus | 权限 Dialog 打开时焦点必到按钮；关闭后回触发点 |
| 卡片焦点 | Fluent `focusMode` 四档 | 时间线工具卡用 `tab-only` 或 `off`+显式按钮，避免 trap 迷宫 |
| 对比 | WCAG AA：正文 4.5:1 | 状态色旁必须有图标/文字，不只靠颜色 |
| Reduced motion | OS `prefers-reduced-motion` | 见 Topic 11；保留 loading/progress 反馈 |
| 键盘 | 全功能可达；disclosure 控件可键盘操作 | 审批 Allow/Deny 快捷键；Composer Ctrl+Enter 可配置 |
| 屏幕阅读 | 消息流 `role="log"` 或 polite live；流式更新节流 aria | 避免每 token 都 announce |
| 命名 | icon button 必须 `aria-label` | Tool card 上的 copy/retry/expand |

**Electron**：Chromium a11y 可用；注意自定义 titlebar 的键盘；`prefers-reduced-motion` 用 `matchMedia` 同步到 store。

**Sources**: [Fluent MessageBar a11y](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage) · [Fluent Card a11y](https://fluent2.microsoft.design/components/web/react/core/card/usage) · [LobeHub DESIGN.md Do/Don't](https://github.com/lobehub/lobehub/blob/canary/DESIGN.md) · [M3 Reduced Motion](https://www.designref.ai/design-systems/material-design/motion)

### 10. 响应式密度与桌面布局

Windows 桌面 Agent 典型视口：1280–2560 宽；密度偏「专业工具」而非移动宽松。

**LobeHub 布局节奏（4px scale）**：

| Token | px | 用途 |
|-------|----|------|
| XXS/XS | 4/8 | 组内、chip、icon 间距 |
| SM | 12 | 控件内边、次级间距 |
| base | 16 | 卡片 padding 下限、组间 |
| MD/LG | 20/24 | 卡片 padding、区块间 |
| XL | 32 | 大区块/页边 |

- 组内 8px → 组间 16px → 区块 24–32px
- 圆角**独立标度**（4/6/8/12），勿与 spacing 混用
- 控件高：28 / 36 / 40；图标尺寸 12–20 是 dimension 不是 spacing
- 离标度值（6/10/13）视为漂移，四舍五入到标度
- 主内容居中，宽屏增大侧边 padding；每表面同时有 light/dark 与 desktop/mobile 变体

**Agent 布局建议**：

```
┌──────────┬────────────────────────────┬────────────┐
│ Session  │  Chat / Tool timeline      │ Detail     │
│ sidebar  │  (virtualized)             │ Drawer     │
│ 240–280  │  flex 1                    │ 0 / 360    │
│          │  Composer bottom           │ diff/logs  │
└──────────┴────────────────────────────┴────────────┘
```

- 窄窗（<1100px）：Drawer 覆盖式；sidebar 可折叠图标栏
- 消息内容最大阅读宽 ~720–780px，两侧留白
- 工具卡时间线左侧 gutter（状态点/线）固定 24–32px

**Sources**: [LobeHub DESIGN.md Layout/Elevation](https://github.com/lobehub/lobehub/blob/canary/DESIGN.md)

### 11. 动效原则（Material Motion + LobeHub + Fluent）

#### M3 Motion Tokens（可直接作 CSS 变量）

**原则语义**：
- **Emphasized** — 需要注意力的主进出场
- **Standard** — 常规状态变化
- **Decelerate** — 入场减速
- **Accelerate** — 出场加速

**缓动曲线**：

| Token | cubic-bezier | 用途 |
|-------|--------------|------|
| Emphasized | `0.2, 0, 0, 1` | 主表达性动效 |
| Emphasized Decelerate | `0.05, 0.7, 0.1, 1` | 元素进入 |
| Emphasized Accelerate | `0.3, 0, 0.8, 0.15` | 元素离开 |
| Standard | `0.2, 0, 0, 1` | 最常见过渡 |
| Standard Decelerate | `0, 0, 0, 1` | 标准进入 |
| Standard Accelerate | `0.3, 0, 1, 1` | 标准退出 |

**时长标度**：

| 档 | ms | Agent 示例 |
|----|-----|------------|
| Short 1–4 | 50–200 | 状态点/开关/checkbox；tool 状态切换 |
| Medium 1–4 | 250–400 | 卡片展开/折叠；导航；**默认 300ms** |
| Long 1–4 | 450–600 | 大面板/路由切换 |
| Extra Long | 700–1000 | hero / stagger；**少用** |

#### LobeHub Motion 原则（桌面 Agent 很贴）

- **动效澄清变化，永不作装饰**
- 状态变化/popover：**100–200ms**
- overlay/modal：**≤300ms**
- 避免长循环、抢注意力的动画
- AI/loading 用专用 loader，不用杂牌 spinner

#### Reduced Motion 策略

| Keep | Remove | Replace |
|------|--------|---------|
| opacity fade、简单颜色过渡 | slide/scale/rotate/parallax | 复杂进出场 → 瞬时或 fade |
| loading/progress 反馈 | — | — |

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

**Apple HIG Motion**（站点需 JS，未能抓取原文）：通用原则仍适用——动效应有物理感与目的性、支持 Reduce Motion、避免闪烁/大幅闪烁（photosensitivity）。实现时以 M3 数值 token + LobeHub 时长预算为准。

**Sources**: [DesignRef M3 Motion](https://www.designref.ai/design-systems/material-design/motion) · [LobeHub DESIGN.md Motion](https://github.com/lobehub/lobehub/blob/canary/DESIGN.md)

### 12. 微交互（Micro-interactions）

| 场景 | 动效 | 时长/曲线 | 备注 |
|------|------|-----------|------|
| 工具状态 running | 状态点 pulse / spinner | 循环但幅度小 | reduced-motion 下改静态色变 |
| 工具 success | check 短弹入 | 150–200ms emphasized-decelerate | 不要撒花 |
| 工具 error | 图标色变 + 轻微 shake（可选） | ≤200ms | shake 默认关，设置可开 |
| 卡片展开 | height/auto + opacity | 200–300ms standard-decelerate | 配合 Disclosure |
| 新消息入场 | fade + 4–8px rise | 200ms | 虚拟列表插入动画要节流 |
| 流式 caret | 光标闪烁 | CSS | 勿每字符布局抖动 |
| 按钮提交 | pressed fill `colorFillQuitter/Active` | 即时 | disabled + spinner 按钮内 |
| Toast 入场 | 自底/角 slide+fade | 200–300ms | 自动消失 4–6s，error 可更长或钉住 |
| 审批卡获得焦点 | warning 边框/阴影抬升 | 100–200ms | 窗口失焦时 Tray 提醒 |
| 拖分栏 | 无弹性过冲 | 即时 | 桌面工具优先精确 |
| 复制成功 | icon → check + tooltip「Copied」 | 1.5s | 不要 Toast 刷屏 |

**原则**：微交互回答「系统在干什么/我刚做了什么」；禁止无信息装饰动效（LobeHub）。

### 13. Agent 状态指示器

**全局状态（标题栏 / 侧栏 Agent 头）**：

| 状态 | 视觉 | 文案（可选） |
|------|------|--------------|
| idle | 中性点 | Ready |
| thinking | info 点 pulse / 轻 spinner | Thinking… |
| streaming | primary 点 + 正文 caret | 无需文案 |
| tool-running | info + 活动图标 | Using {tool}… |
| waiting-approval | **warning 醒目** + Badge(1) | Needs your approval |
| error | error + Retry | Something went wrong |
| offline/provider down | error badge | Provider unreachable |

**列表会话状态**：Badge/点叠加在 Avatar（Fluent Avatar 支持 status/activity）。

**时间线活动**：垂直 timeline 步骤（LobeHub/Open WebUI workflow）：
- 每步：状态点 + 标题 + 相对时间
- 当前步可展开；已完成折叠
- 与 Task 工具（task list）同构：`open/in_progress/done/blocked`

**文案（LobeHub）**：进行中用现在分词 + 省略号（`Generating…`、`Saving…`）；同一动作全应用同一动词（Create/Run/Pause/Retry…）。

### 14. 审查 / Diff 面板

Agent 写文件/改代码时的 Review UX：

| 模式 | 说明 | 组件 |
|------|------|------|
| Inline tool preview | 工具卡 Preview 只显示 +N/−N 与文件名 | Card preview |
| Side-by-side Drawer | 原文/新文对照，等宽字体 | Drawer + Monaco 或 diff2html |
| Unified diff | 单栏 ± 行；默认给工程师 | 可滚动代码块 |
| 批量文件列表 | 文件树 + 每文件变更计数 + 全选/单选应用 | Tree + checkbox |
| 操作 | Apply all / Apply selected / Discard / Edit & apply | Toolbar |
| 语法 | 文件名 + 语言；对比 gutter 行号 | token 化代码 |

**规则**：
1. **未应用的变更永不静默写入**——需显式 Apply 或权限策略允许
2. Diff 大文件时虚拟化 + 默认只渲染变更块附近上下文（如 3 行），可 “Show more”
3. 错误 diff（补丁失败）→ MessageBar(error) + 提供重试/打开编辑器
4. 与权限 UI 组合：Write 工具 → 卡内嵌 mini-diff → 批准后执行；或执行后 review 模式
5. 焦点与键盘：J/K 下一/上一变更，A apply，X discard（可设置）
6. Electron：主进程应用补丁；渲染层只展示；成功后 Toast 命名路径
