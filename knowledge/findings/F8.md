## 主题发现（≥10）

### T1 · OpenAI 兼容 API：桌面 Agent 的「默认落脚点」

**密集主张**

- OpenAI-compatible 形态已成多供应商事实基线：OpenCode 对任意兼容端点用 `npm: "@ai-sdk/openai-compatible"` + `options.baseURL` + `models` map 接入（S2，llama.cpp `http://127.0.0.1:8080/v1`、LM Studio `:1234/v1`、Ollama `:11434/v1`、Atomic Chat `:1337/v1`）。
- Aider 用环境变量 `OPENAI_API_BASE` + 模型前缀 `openai/<model-name>` 接入任意兼容端点；对不熟悉的模型会触发 *model warnings*（S5 openai-compat）。
- Yan-Agent 1.5.0 把「连接」抽象为用户自建条目：名称、Base URL、API Key、兼容预设、可选媒体 POST 端点；`lib/connection-presets.js` 预设集合为 `auto|openai|anthropic|deepseek|glm|qwen|doubao|gemini|kimi|minimax|siliconflow|grok|agnes|stepfun|hunyuan|opencode|sensenova|jiyuan`；**apiFormat 只分两档**：`preset==='anthropic' ? 'anthropic' : 'openai'`（S7）。
- 预设推断是**字符串启发式**（name+baseUrl 含 `deepseek`/`bigmodel`/`moonshot`/`dashscope`/`ark.cn` 等），默认回退 `openai`；无需与厂商模型清单同步（S7 `connection-presets.js:15-34`）。
- 兼容端点常见坑：Azure deployment name 必须与模型名一致或用 `models[id].id` 显式映射（S2 Azure）；本地模型 tool-calling 弱时要选 strong tool 模型（Qwen-Coder/DeepSeek-Coder），Ollama 需提高 `num_ctx`（16k–32k）（S2）。

**俱佳Agent 可复用点**

1. 连接配置最小 schema：`{id, name, baseURL, apiKey, preset, mediaEndpoints[], manualModelId}`。
2. `apiFormat` 二值化 + 预设可覆盖；不要在 UI 写死 14 个厂商表单。
3. 自定义 provider 一律走 OpenAI-compatible 适配器；Anthropic 原生 Messages 单独分支。

### T2 · Anthropic Messages API 与 thinking / tool_use

**密集主张**

- 官方 `platform.claude.com` / `docs.anthropic.com` 在本研究环境被区域跳转，**协议细节以实现侧证据为准**（源：Yan `@ai-sdk/anthropic@3.0.42` + OpenCode Anthropic provider 文档 S2/S7）。
- Anthropic 作为 OpenCode 一等 provider：`/connect` → API Key 或浏览器 OAuth；`provider.anthropic.options.baseURL` 可改（默认 `https://api.anthropic.com/v1`）；可用 `blacklist`/`whitelist` 过滤模型 ID（S2）。
- OpenCode ≥1.3.0 **不再捆绑** Claude Pro/Max 订阅透传插件（Anthropic 明确禁止）；官方侧仅明确支持 ChatGPT Plus / GitHub Copilot / GitLab Duo 订阅接入（S2）。桌面 Agent 不要把订阅号当 API 钥匙用。
- Claude Code 源码分析（S6）指出：核心是 `while(true)` 的 **model→tools→repeat** 循环（`query.ts` ~68KB + `query/` 辅助模块）；扩展面为 **MCP + Plugins + Skills + Hooks** 四机制；权限 **7 modes + ML classifier**；上下文 **五层 compaction**（budget reduction / snip / microcompact / context collapse / auto-compact）；memory 走 `CLAUDE.md` 层级 + memdir；session append-only，**resume/fork 不恢复权限**。
- Anthropic Messages 响应中 thinking 块与 tool_use 块需在多轮对话中原样回传（行业共识 + Claude Code 事件流设计）；俱佳Agent 适配层应把「thinking 可见性」与「工具结果回写」拆开处理。

**俱佳Agent 可复用点**

1. Provider 分支：`anthropic`（Messages, thinking/tool_use/blocks）vs `openai-compatible`（chat.completions, tool_calls）。
2. 对话历史不能只存扁平 string；需要 block 级 transcript（text/thinking/tool_use/tool_result）。
3. 不依赖 Claude 订阅透传；只接标准 API Key / 中转 Base URL。

### T3 · 流式 SSE：解析、事件源、桌面批处理

**密集主张**

- OpenAI Chat Completions 流式：`stream:true`，SSE `data:` 行，chunk 含 `choices[0].delta.content` / `delta.tool_calls` / `finish_reason`；`[DONE]` 结束（社区实现与 Yan 自研路径一致）。
- Yan-Agent 将 `eventsource-parser` 打进 asarUnpack（`package.json:75`），说明 **SSE 解析在 Node/主进程侧**，而不是只靠渲染层 fetch（S7）。
- OpenCode 侧 Yan 通过 `lib/opencode-sidecar.js` 连接 loopback 认证 server，把模型消息/工具/权限/压缩/媒体/错误等**结构化事件流**推给桌面 UI，避免「静态转圈」（S7 README §1）。
- 稳定性：断流最多 **5 次重连**；prompt 路径 `PROMPT_RETRY_ATTEMPTS=3`（1+2），线性 backoff 1000ms；poll 路径 3 次 × 200ms；session 消失 grace **10s**（S7 `lib/opencode-stability.js`）。
- 瞬时错误分类（可重试）：`stream interrupted`、`generation stalled`、`incomplete tool call/dsml`、`socket hang up`、`fetch failed`、`ECONNRESET/ABORTED/TIMEOUT`、`429`、`5xx`、`rate limit`、`DeepSeek 工具调用适配失败` 等；**配置/鉴权/上下文溢出/用户取消不重试**（S7）。
- 高频事件批量递交 + 可并发 OpenCode runtime 复用，是 1.5.0「更快速输入与流式链路」的官方描述（S7 README）。

**俱佳Agent 可复用点**

1. Electron：SSE/HTTP 在 **main 或 utility process**；渲染层只消费 typed events（IPC/WebSocket）。
2. 统一 `StreamEvent` 枚举：`text_delta | thinking_delta | tool_call | tool_result | usage | error | done`。
3. 重试策略单点模块（transient classifier + bounded retry + abortable delay），禁止在 run 循环里嵌套重试。

### T4 · `reasoning_content` / thinking 块 / reasoning 配置位

**密集主张**

- DeepSeek 系兼容 API 常见响应字段 `message.reasoning_content`（与 `content` 并列）；Yan 视觉中继在 content 为空时回退读取 `reasoning_content`（S7 `vision-relay.js:76`）。
- 正文内嵌 `<thinking>…</thinking>` 的模型需要**流式切分器**：Yan `lib/thinking-text.js` 用 OPEN/CLOSE 标签扫描，并处理**标签前缀不完整**（trailing tag prefix held-back）场景，避免半截 `"<think"` 泄漏进用户正文（S7）。
- Aider 的 reasoning 适配（S5）：
  - `--reasoning-effort`（OpenAI o 系 low/medium/high）
  - `--thinking-tokens`（Anthropic Sonnet 预算，如 `8k`）
  - `reasoning_tag`（如 Fireworks DeepSeek R1 的 `think`）
  - **`accepts_settings` 白名单**：模型 metadata 声明才允许设置；未声明则警告并忽略（可用 `--no-check-model-accepts-settings` 强推）
  - 推理模型常禁：`temperature`、`streaming`、`system_prompt` → `use_temperature:false` 等开关
- Claude Code 论文（S6）强调：thinking/内部工作过程应可折叠审计，但**最终用户回复用模型原生最终输出**；Yan 1.5.0 同样「直接使用模型最终回复，不再额外无工具总结回合」，内部过程可展开（S7）。

**俱佳Agent 可复用点**

1. 模型 capability：`reasoning: 'none' | 'content_field' | 'xml_tag' | 'effort_enum' | 'thinking_tokens'`。
2. UI：thinking 默认折叠；正文与 thinking 分通道渲染；协议标记（DSML/XML）过滤后再展示。
3. 设置项按模型白名单下发，避免 API 400。

### T5 · 多供应商适配器：AI SDK、模型目录、网关

**密集主张**

- OpenCode 技术底座：**Vercel AI SDK + Models.dev** 支撑 **75+ LLM providers**，并支持本地模型（S1/S2）。
- 自定义 provider 配置形状（OpenCode / S2）：

```json
{
  "provider": {
    "<id>": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Display Name",
      "options": { "baseURL": "http://127.0.0.1:PORT/v1", "headers": {} },
      "models": { "<model-id>": { "name": "...", "limit": { "context": 128000, "output": 65536 } } }
    }
  }
}
```

- 凭据默认落盘 `~/.local/share/opencode/auth.json`（`/connect` 写入）（S2）。
- Yan 直接依赖：`@ai-sdk/anthropic@3.0.42`、`@ai-sdk/openai-compatible@2.0.41`、`@opencode-ai/sdk@1.18.11`、`opencode-ai@1.18.11`、`opencode-windows-x64@1.18.11`（S7 package.json）。
- LiteLLM 类网关（S8，二手）：统一 OpenAI 形态调 100+ providers；异常映射为 OpenAI 风格；常用于代理/计费/限流。OpenCode 目录中亦收录 Cloudflare AI Gateway、Helicone、Vercel AI Gateway、OpenRouter、Eden AI（`vendor/model` 三段 ID）等（S2）。
- Roo Code（S4）产品特征：**API Configuration Profiles** 一次性切换「Provider+模型+Key+温度+限速」整套配置；Modes 四+自定义。扩展已关停，社区分叉 **ZooCode**。

**俱佳Agent 可复用点**

1. 适配层优先复用 `@ai-sdk/openai-compatible` + `@ai-sdk/anthropic`（与 Yan 同栈，Windows 可打包）。
2. Provider 注册表 = `{id, npm/adapter, baseURL, headers, models[], limits}`。
3. 「连接 Profile」概念照搬到桌面设置页；运行中切配置需 **sidecar 无活跃 run 才重启**（Yan 规则）。

### T6 · 视觉 / 图片 / 视频模型：角色拆分与视觉中继

**密集主张**

- Yan 三角色互不抢上下文（S7 README §8）：
  1. **主文本模型**：理解/规划/工具/最终交付
  2. **生图模型**：生成或编辑图片，结果回到主模型解释
  3. **生视频模型**：同理；二者可空
- 图片比例支持：`auto, 1:1, 4:3, 3:4, 3:2, 2:3, 16:9, 9:16, 21:9`；会话内修改媒体**复用资源 ID**，不要求重新上传。
- **视觉中继**：主模型不能读图时，按序 `glm → sensenova → agnes → 硅基流动` 生成读图报告再交回主模型；不把图中文字当工具指令（S7 README §8）。
- 能力目录：`lib/model-capabilities.js` 维护 `STATIC_VISION_MODEL_IDS` / `STATIC_TEXT_ONLY_MODEL_IDS` + `PROVIDER_IMAGE_MIME_TYPES`（openai 多格式，grok 仅 png/jpeg 等）——**能力用静态表 + 运行时接口校验双轨**，目录可用 ≠ 远端可用。
- 媒体适配：`lib/video-generation.js` 按 provider 分支 create/status URL 与 duration 上限（grok≤15s；openai/qwen/glm/doubao/minimax/siliconflow 各自 body 形状）；支持用户自定义 `providerOptions.videoGenerationUrl` 与 `adapterKind` 覆盖。
- GLM `/models` 可能只返回文本模型 → 目录层用 **官方 supplemental 列表**补 vision/image/video 条目（S7 `provider-model-catalog.js`，`MODEL_SOURCE_GLМ_OFFICIAL` 等）。
- 视觉中继限流：403/429 + 文案匹配（rate limit/限流/频率限制…）→ 换下一中继；图片 >20MB 拒绝；timeout 默认 120s（S7 `vision-relay.js`）。
- 「生成成功 ≠ 再 read_image」：避免无谓二次视觉消耗；仅任务需要时才读图（S7）。

**俱佳Agent 可复用点**

1. Model Role 分离：`text | image_gen | video_gen | vision_relay`；设置页分别绑定连接。
2. 附件过滤：按主模型 capability 决定文件选择器是否显示图片。
3. 中继链 + 限流降级，而不是单模型硬失败。

### T7 · 模型目录 / 回退 / 白名单黑名单 / 廉价小模型

**密集主张**

- 目录来源分层（S7/S2）：
  - **API 动态发现**（OpenAI/Grok/Agnes/GLM/SiliconFlow 等尽量 `GET /models`）
  - **内置回退目录**（只服务配置 UI）
  - **官方补充目录**（API 不全时的静态补丁，标注 source）
  - **用户手填 model ID**（私有部署）
- OpenCode：`whitelist` 只保留列出模型；`blacklist` 排除；可组合；自定义 inference profile 用 `models[id].id` 映射 ARN/deployment（S2 Bedrock/Azure）。
- **small_model**：OpenCode 自托管场景建议 `"small_model": "gitlab/duo-chat-haiku-4-5"` 锁定会话标题等轻任务，避免默认 Zen `gpt-5-nano` 泄漏到外部（S2 GitLab）。
- Aider 双模型：主模型 + weak/editor 模型（如 sonnet 主力、`gpt-4o-mini` weak、`gpt-4o` editor），配合 `edit_format`（diff/editor-diff）与 repo map（S5）。
- Yan 推理速度三档：`标准 / 高效 / 更智能`，实时回写输入框状态线（S7 README §11）。
- OpenCode Zen / Go：团队测过的 curated 模型列表 + 订阅入口，作为「推荐默认」而非硬依赖（S2）。

**俱佳Agent 可复用点**

1. Catalog 状态机：`live > supplemental > fallback_static > manual`，UI 显示 source 徽章。
2. 每个能力位允许独立模型 ID：`primary | planner | title/small | vision | image | video`。
3. 模型卡片字段：`context_limit, output_limit, vision, tools, reasoning, price_unknown`（**不展示价格承诺**，Yan 原则）。

### T8 · 限流、熔断、缓存观测与用量审计

**密集主张**

- 可恢复 HTTP：`403/429/408/500/502/503/504`（视觉中继）；OpenCode stability 更宽（429/5xx + 网络错误文案）（S7）。
- **重复错误熔断**：同类错误持续重复时停止消耗，而非无限重试（S7 README §1）。
- 缓存：完成头部展示 **真实 usage**（cache read、input total、命中率），禁止伪造百分比（S7 README §9/§11）。
- 审计：每次运行保留 OpenCode session ID、工具事件、用量、变更摘要、最终状态（S7 README §1）。
- 网关层（Helicone 等）可注入 `Helicone-Cache-Enabled`、`Helicone-User-Id`、`Helicone-Session-Id` 等 header 做缓存与可观测（S2）。
- Claude Code 论文（S6）将 **silent failure / observability–evaluation gap** 列为未来方向；桌面 Agent 必须把「模型自称完成」与「工具证据」分离。

**俱佳Agent 可复用点**

1. Usage 事件：`{input_tokens, output_tokens, cache_read, cache_write, cost:null}`。
2. 熔断器：同 error fingerprint 连续 N 次 → run fail-fast + UI 错误态。
3. 限流退避：尊重 `Retry-After`；多连接时按连接粒度冷却，不全局杀会话。

  - 执行权威 = OpenCode sidecar（`lib/opencode-sidecar.js` + loopback auth）；**旧 Yan V1/V2 renderer agent loop 已删除**
  - XDG/`OPENCODE_TEST_HOME` 隔离到 `YanData/opencode-runtime`，防全局 `.claude/.agents/.opencode` 污染

- Yan MCP（JSON-RPC 2.0 over stdio）：Built-in Browser、Yan Skills、CodeGraph、Serena、Yan Media、Yan Session、Yan Computer Use（Nuphus `desktop_*`）、Yan Harness、Playwright 后备；**每任务工具快照**，服务不可用不伪装工具（S7 README §6/§MCP 表）。
- 记忆（S7 README §10）：
  - 短期：OpenCode 会话消息+工具结果+权限+验收态
  - 压缩：~**70%** 软压缩、~**85%** 硬安全线；最小窗口 16k；保留区 ≤24k 且 ≤窗口 25%

  - 会话交接上限：24 条消息 / 64k 字符 / 单条 6k（`Yan Session` MCP；**不带权限/审批**）
- 工具暴露策略：按任务需要暴露；Blank 工作区禁止文件写入类操作（Skill 安装例外，只写 Yan skill root）（S7）。

**俱佳Agent 可复用点**

1. 学习期直接 pin 一个 OpenCode release 做 sidecar，Electron 只做壳；**不要双内核**。
2. 主进程持有权限与运行状态；渲染层零猜测。
3. 目录/技能/MCP 与上游隔离：自有 data dir + env hooks；升级 checklist。

### T10 · Cline / Roo Code：IDE 系 Agent 的工具循环与多供应商

**密集主张**

### T12 · OpenHands / Continue / 网关型方案

**密集主张**

- OpenHands（检索摘要 S8 相关 Bing 结果 + openhands.dev/docs）：定位 **AI-Driven Development 平台**；开源 MIT 系谱（原 OpenDevin）；强调 **sandbox/runtime 执行真实工程**，而非仅补全；模型无关；有 Cloud GUI 商业部署 + 本地/服务器安装路径。架构对桌面 Agent 的可借鉴点：**动作在隔离运行时执行**、事件流驱动 UI、模型可插拔。
- Continue（docs.continue.dev 在本环境 404，依据社区/检索）：VS Code 扩展，核心价值在 **多模型配置文件**（chat/autocomplete/embed/rerank 多槽位）与本地模型（Ollama/LM Studio）接入；Yan 借鉴点是「同一产品多模型槽位」而非 IDE 嵌入。

**俱佳Agent 可复用点**

1. 桌面版不必复制 OpenHands 的完整 Docker 沙箱，但 **workspace 路径权限** 与高风险命令分类必须有。
2. 设置页模型槽位：primary/edit/vision/image + autocomplete（若做编辑器联动）可延后。
3. 供应商优先：OpenAI-compatible 自建连接 > 一键网关。

## 对俱佳Agent 的集成设计要点（可执行）

1. **Provider 抽象**：`Adapter = { id, apiFormat: 'openai'|'anthropic', chat(), stream(), listModels(), capabilities(modelId) }`；OpenAI-compatible 覆盖 80% 场景。
2. **连接即产品对象**：用户可建无限连接；文本/图片/视频角色独立绑定；切换不静默改运行中的 run。
3. **Stream 管道**：`Adapter → normalize(thinking|content|tool_calls|usage) → EventBus → UI`；thinking 与 protocol 标记过滤在 normalize 层完成。
4. **能力表**：`vision / tools / reasoning_kind / context / media_gen`；静态表 + 实测探测；UI 文件选择与中继路径由能力表驱动。
5. **稳定性单点**：transient classifier（参考 `opencode-stability.js` 模式列表）+ 重试预算 + 熔断 + 可见错误态。
6. **内核策略（学习两阶段）**：
   - 阶段 A：Electron 壳 + 自研最小 tool loop（读/写/bash/edit），自定义 OpenAI-compatible 适配。
   - 阶段 B：引入 OpenCode sidecar（或仅复用其 provider/压缩思想），对齐 Yan 的隔离与事件模型。
7. **权限与工作区**：主进程权威；Blank 不写盘；高风险命令分类；审批结果绑定 run 而非全局会话泄漏。
8. **记忆**：三级文件记忆 + 证据字段；交接设硬上限；注入过滤。
9. **UI 可观测**：真实 cache/usage、压缩事件、工具时间线、审阅 diff、可展开 thinking。
10. **反模式**：双 agent loop；渲染层自管权限；目录写死价格/免费额度；无限重试；生成图片后强制二次 read_image。
