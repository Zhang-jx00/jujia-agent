## 复核 011 · 对象：dev 管线修复（plugin-react 6→5.2）—— 轻量轮

复核基线：`v0.14.2-devfix` 提交前的修复内容（含探针脚本）

### 背景

用户实测 `npm run dev` 黑屏，vite 报 `Missing field 'moduleType'`。定位结论（见 CHANGELOG v0.14.2）：
`@vitejs/plugin-react@6.x` peer 要求 vite ^8，与 electron-vite 5（vite ^5–7）+ vite 7.3.6 组合非法。
**这条坏链路自依赖选型起就存在 —— dev 模式此前从未被运行过。**

### 第一遍 · 状态与一致性

| 检查项 | 结果 |
|--------|------|
| 版本树核对（`npm ls vite`） | plugin-react 5.2.0 / electron-vite 5.0.0 / desktop 三方**解析到同一个 vite 7.3.6**；根下的 vite@8.3.0（vitest 5 所需）不再被渲染层 dev 使用 |
| 联网核实（npm registry 元数据，2026-09-21 22:10） | plugin-react 6.x peer = `vite ^8`；5.x peer 含 `^7`；electron-vite 5 peer = `^5||^6||^7` → 升级线走不通，降级是唯一干净解 |
| 目录整洁 | 新增脚本落在 `apps/desktop/scripts/`，与既有脚本同层 |
| 四件套实跑 | typecheck 通过 · lint 0 error（脚本里 4 处全局 `fetch` 触发 no-undef，已改 `globalThis.fetch`）· 全量 **480/480** · smoke **OK** |

### 第二遍 · 变异与空转断言（本轮的重点教训）

新增探针 `verify-dev-transform.mjs`（无头起 dev server → 真的请求渲染层模块 → 断言 react 插件生效）。
**第一版探针是摆设**，被两个假象骗过，变异（移除 `react()`）竟然通过：

| 假象 | 为什么会骗过 | 修正后的断言 |
|------|--------------|--------------|
| esbuild 的 automatic JSX | 它也会产生 jsx-runtime 引入，与"插件是否生效"无关 | 改看**只有 react 插件才注入**的 `$RefreshReg$`（组件模块） |
| SPA 回退 | dev 对未知路径返回 **200 的 HTML**，状态码 200 ≠ 端点存在 | 改看 content-type 必须是 JS 且正文非 HTML |

修正后：正常态通过；变异（移除 `react()`）被拦住，且两条诊断信息分别命中两个断言；
还原后探针复跑通过、`electron.vite.config.ts` 与 HEAD 逐字节一致。

**这条教训与复核 007（注释过滤）、010（空转测试）同源**：断言必须钉住"只有目标实现才有的特征"，
否则测试存在、跑过、也绿，但什么都没锁住。区别在于这次是**我自己在写探针的当场被变异抓住**——
先变异再交差这个顺序又一次证明是对的。

### 静默失败嗅探

探针所有失败分支都带**可操作的中文诊断**（含 HTTP 状态与 content-type），
且任何一项失败都会以非 0 退出 —— 不会出现"绿了但实际没查"。

### 结论

修复有效（探针 + 四件套全绿），探针自身经变异验证非摆设。
**无未处置问题 → 允许进入下一阶段。**
**流程改进（待用户确认后固化）**：把「`npm run dev` 至少启动一次 + `verify-dev-transform` 探针」
纳入每阶段收尾清单 —— 本轮证明"构建绿"与"dev 能用"是两回事。

### 第二遍 · 端到端对抗性实验

关键对抗用例：① matcher 未命中时**一个进程都不起**；② 含 shell 元字符的命令**直接拒绝且不 spawn**；

stderr（钩子的日志带进诊断）· 输出截断（记诊断）。

### 复核发现并修掉的一个**解析陷阱**（这就是先做策略层的价值）

- `http:///path` 会被 URL 解析器"修好"：**`path` 被提升成主机名** ——
  等解析完再检查"有没有主机"就查不出来了。修复：**先对原始输入做结构校验**（`scheme://` 后必须有主机），再解析。
- `https://ht!tp://x` 的主机是 `ht!tp`（WHATWG 允许主机里有 `!`）→ 主机字符集收窄为 域名/IP 形态。
- `http://999` 会被规范化成 `0.0.3.231`（合法的 IP 缩写）→ 放行（它确实是合法主机）。

### 操作禁忌（踩坑后固化）

| 禁忌 | 原因 | 正确做法 |
|------|------|----------|
| 用 `git checkout -- <file>` 还原变异/临时改动 | 会连带丢弃同一文件里**未提交**的修复（R2-9 实测：变异还原后功能再次损坏） | 变异测试只在**已提交的干净基线**上做；还原用精确补丁或临时副本（`cp` 备份 → 改 → 还原） |
| 在 `%APPDATA%` 等**项目目录外**路径用 `rm` | 沙箱安全删除会 fail-closed 拦截（R2-8），脚本中途失败 | 用 Node `fs` 操作运行时数据；项目内文件清理统一走 `scripts/cleanup.py` |
| 只等 `did-finish-load` 判定前端就绪 | 该事件早于 React 首帧与 IPC 回包 | 轮询等待（200ms × 8s）并断言业务标记 |
| 把校验写成"用同一常量既定义期望又定义实际" | 自引用校验：常量改坏时两层同时失效（R2-1） | 断言使用独立字面量真值，并单测锁死常量 |
