## 1. 理论依据（2026-09-21 联网核实）

### 1.1 保罗·兰德的四条方法（抽象标记的权威框架）

| 原则 | 含义 | 对我们的约束 |
|------|------|-------------|
| **蒸馏（Distillation）** | 把复杂概念缩减为**单一简单形式** → 跨尺度可识别、不过时 | 不做"盾牌+宝石+星光"的堆叠；最终必须收敛到一个形式 |
| **本质形式（Essential Forms）** | 用圆/方/三角等**几何基元**，剥掉渐变、阴影、细节，到"几乎骨架化" | 只用矩形与圆角；无渐变、无阴影 |
| **隐喻与抽象** | 不画实物，**暗示概念**，让观者参与解读 | 用结构而非插图表达"认真对待你的机器" |
| **网格系统（Grid）** | 网格保证**结构完整性**与比例一致，从 favicon 到广告牌都成立 | 所有笔画落在网格上；参数化生成 |

### 1.2 极简设计的七条原则

1. **简洁** —— 检验法："**你能凭记忆画出来吗？**"
2. **负空间** —— 是主动设计元素（FedEx 的隐藏箭头）；**排他区约等于一个字高**
3. **限色** —— 1–2 色；**先在黑白下设计**，黑白立不住加色也救不了
4. **几何形** —— 数学精确 → 无限缩放不失真
5. **字标优先** —— 纯字标同样成立（IBM / Sony / Netflix）
6. **可缩放** —— **16×16 检验**：在 16px 下分不清形状，就是还不够极简
7. **不过时** —— 十年后是否仍成立

### 1.3 汉字字标专门方法（这部分最关键）

| 方法 | 要点 |
|------|------|
| **识别性优先** | 标志第一功能是识别；**变形控制在 30% 以内**；检验法：不同年龄段**2 秒内**能否认出 |
| **别过度拆减** | **"增减笔画会使人难以辨认"**；"避免对字形和基本结构进行过度拆减" ← **我第一版就栽在这里** |
| **几何化** | 主流路线（小米/OPPO）：**横笔统一厚度、竖笔统一另一厚度**；转角规整；拆开看每个字都是几何图形拼的 |
| **主动删笔画** | 简化**次要/重复**笔画（如「口」化简为空心矩形）——但以"仍能认出"为底线 |
| **负空间当骨架** | 笔画密集处增间距；**黑白反相检验**：反转后仍能看清轮廓与疏密节奏才算到位 |
| **重心** | 汉字自然重心在几何中心**偏上一点**；科技类偏上（挺拔），亲和类偏下（敦厚） |
| **先定字重再设计** | 科技类取**中等字重**（平衡感）；先定横竖粗细比例再画，效率翻倍 |
| **灰度测试** | 转纯黑白、缩到 **20px**，一眼能认出品牌名才算过关 |
| **圆的规范** | 圆角必须是**正圆**，弧线用正圆/椭圆规范，不能随手画 |

**参考案例**：蜜雪冰城（圆润笔画 + 口字旁几何化）、喜茶（调节字间与笔画间距让上下通透）、
三只松鼠（加长横画 + 压缩间距形成块面感）、北京大学校徽（"北大"图形化为脊梁意象）。

## 2. 设计定位（结论）

- **风格**：几何化极简笔画（对应"趋势一：从书法感转向几何化"）
- **字重**：中等（开发者工具 → 平衡感、可信）
- **重心**：略偏上（约 46%），传达"精准、可靠"
- **颜色**：主色 `#4c8dff`，深底 `#101820`；**必须先出黑白单色版**
- **负空间**：字间距与笔画间距作为主动元素；排他区 = 一个字高

## 3. 第一版设计（手工几何构造）

做法：把「俱」「佳」都拆成**横/竖矩形**，参数化生成 SVG
（`apps/desktop/scripts/make-logo.mjs`，可复现：`node apps/desktop/scripts/make-logo.mjs`）。

- 两字**共享同一组「亻」参数**（笔画共用的思路）
- 「佳」的「圭」用 1 竖 + 4 横（纯几何）
- 「俱」的「具」做了**笔画减省**：目框内由 2 横减为 1 横

## 4. ⚠️ 第一版失败记录（如实记载，不掩盖）

**结果：渲染出来完全读不出「俱佳」** —— 左字像"方框上加十字"，右字像"F / 梯子"。

**失败原因（对照理论逐条）**：

| # | 我做的 | 理论怎么说 |
|---|--------|-----------|
| 1 | 把「亻」简化成"两条错位横 + 一竖" | 这已经不是「亻」了；**增减笔画会使人难以辨认** |
| 2 | 把「具」「圭」的部件等比简化，没有保留**部件间的相对比例** | 汉字靠**间架结构**辨识（部件位置/大小关系），不是靠笔画数量 |
| 3 | 变形幅度远超 30% | **变形控制在 30% 以内** |
| 4 | 用矩形搭骨架，缺少**字体的骨架参照** | 业界做法是"**把字体转成轮廓后**统一横竖厚度"——**先有轮廓，再做几何化** |

**根本教训**：几何化极简的**前提是先有正确的字形骨架**。
我是"从零用矩形拼汉字"，跳过了"轮廓提取"这一步 —— 这需要真正的字体设计功底，
不是几何直觉能替代的。

## 5. 修正后的方法（待执行）

按理论推导，正确路径是「**先轮廓、后几何化**」：

1. **取字形轮廓**：用**开源 CJK 字体**（如 **Noto Sans SC**，SIL OFL 1.1 许可，
   允许使用与修改）取出「俱」「佳」的 glyph 轮廓路径；
   工具：`fontkit`（npm，可把 glyph 导出为 SVG path）
2. **几何化规整**：把所有横笔统一为厚度 A、竖笔统一为厚度 B（理论明确推荐的笨办法），
   转角规整化、端头统一
3. **笔画减省**：仅在**不影响识别**处简化（如重复短横），**每次减省后立刻做 2 秒辨认检验**
4. **重量/重心调整**：重心上移至 46%；字距 = 一个笔画厚度 × N
5. **三重检验**：
   - **黑白反相**（负空间是否成立）
   - **20px 灰度**（一眼能否认出）
   - **16×16**（图标场景）
6. **许可留存**：若使用 OFL 字体，在 `assets/icon/README.md` 里注明字体名、版本、许可，
   并说明字形已做几何化改造

**备选**：若轮廓路线也做不达标，则**降级为"图形标记 + 文字分开"**的方案
（如兰德的 Apple 路线：图标用单一图形，字标另用系统字体排印）——
这比硬做一个读不出的"假汉字"标记更专业。
